## 1교시. 경사 하강부터 모멘텀까지

### 1-1. 옵티마이저는 "조향 장치"

산에서 **눈을 가린 채** 가장 낮은 골짜기를 찾아 내려간다고 상상해 보세요. 눈은 안 보이지만 발바닥으로 "어느 쪽이 내리막인지" 느낄 수 있습니다. 그 느낌이 **기울기(경사)** 입니다.

- 산의 모양 = **손실 표면** (높을수록 많이 틀린 상태)
- 걷는 사람 = **모델**
- 어떻게 걸을지 정하는 규칙 = **옵티마이저**
- 목적지 = 손실이 가장 낮은 골짜기

같은 산이라도 걷는 규칙에 따라 빨리 내려가기도 하고, 제자리에서 맴돌기도 합니다. 오늘은 그 규칙을 배웁니다.

### 1-2. 파라미터란? (슬라이드 6–7)

모델이 **공부하면서 스스로 바꾸는 숫자**입니다. 가장 대표적인 것이 두 가지입니다.

- **가중치 w**: "이 입력을 얼마나 중요하게 볼까?" 입력에 곱해지는 숫자
- **편향 b**: 결과를 통째로 위·아래로 옮기는 숫자 (예: 키와 상관없이 기본 점수 +5점)

한 줄 계산 `y = w·x + b`가 가장 작은 모델입니다. 신경망은 이런 계산을 여러 층 쌓은 것입니다.

**파라미터 개수 세기.** 입력이 n개, 출력이 m개인 층은 가중치가 n×m개, 편향이 m개이므로 **m × (n+1)개**입니다.

- 우리 실습 모델 (64 → 64 → 10): 64×65 + 10×65 = 4,160 + 650 = **4,810개** (코드로도 확인했습니다)
- 큰 모델은 수십억 개 → 매 걸음 그 수십억 개를 어떻게 바꿀지 정해야 합니다. 그래서 옵티마이저가 중요합니다.

### 1-3. 한 번의 훈련 단계 (슬라이드 8)

1. 입력을 넣어 예측을 만든다 (순전파)
2. 정답과 비교해 **손실**(틀린 정도)을 계산한다
3. **역전파**로 "각 파라미터를 바꾸면 손실이 얼마나 변하는가" = **기울기**를 구한다
4. **옵티마이저**가 기울기를 보고 파라미터를 얼마나, 어느 쪽으로 바꿀지 정한다
5. 파라미터를 바꾼다 → 다음 단계 반복

### 1-4. 경사 하강 (슬라이드 9–10)

> θ(새) = θ(옛) − η · ∇L(θ(옛))     (식 14.1)

- θ(세타): 모든 파라미터를 모은 것 (지금 위치)
- ∇L: 손실의 **기울기**. "가장 가파른 **오르막** 방향"
- η(에타): **학습률**. 한 번에 가는 보폭
- **왜 빼나요?** 기울기는 오르막 방향이라서, 내려가려면 반대로 가야 하니까요.

**손으로 한 걸음.** L(θ)=θ²이면 기울기는 2θ입니다. θ=3, η=0.1이면 기울기=6, 새 θ = 3 − 0.1×6 = **2.4**. 손실은 9에서 5.76으로 줄었습니다. 이어서 θ=2.4 → 2.4 − 0.1×4.8 = 1.92 … 매번 θ에 0.8(= 1−2η)을 곱하니 0으로 다가갑니다.

### 1-5. 학습률: 보폭 (슬라이드 11)

| η | 곱해지는 값 (1−2η) | 20걸음 뒤 θ (실측) | 무슨 일이? |
|---|---|---|---|
| 0.01 | +0.98 | 2.003 | 너무 느리다 |
| 0.1 | +0.80 | 0.0346 | 적당하다 |
| 0.9 | −0.80 | 0.0346 | 좌우로 왔다 갔다 하며 수렴 |
| 1.05 | −1.10 | 20.18 | 점점 커진다 = **발산** |

보폭이 너무 작으면 산을 내려가는 데 하루 종일 걸리고, 너무 크면 골짜기를 건너뛰어 반대편 산으로 올라갑니다.

### 1-6. ∇(델)은 뭘까? (슬라이드 12)

∇는 **편미분을 모아 놓은 기호**입니다. 편미분은 "너만 빼고 다 그대로!" 입니다. 변수가 여러 개일 때 **하나만 살짝 움직이고** 나머지는 가만히 두면 결과가 얼마나 변하는지 봅니다. 예를 들어 온도가 (가로, 세로, 높이)에 따라 변할 때, 가로로만 한 칸 움직이면 얼마나 더워지는지.

원본에는 **Gradient(기울기), Divergence(발산), Curl(회전)** 세 가지가 나옵니다. 딥러닝 학습에서 쓰는 것은 **Gradient 하나**입니다. 발산과 회전은 물·전기 같은 물리학에서 쓰는 것이니 "그런 게 있구나" 정도로 넘어갑니다.

### 1-7. 현실의 산은 험합니다 (슬라이드 13)

- **잡음**: 모든 데이터가 아니라 일부(미니배치)로 기울기를 구하므로 매번 조금씩 달라집니다
- **고차원**: 파라미터가 수백만 개 → 어떤 방향은 아주 가파르고 어떤 방향은 거의 평평합니다
- **협곡**: 한쪽은 절벽, 다른 쪽은 완만한 좁고 긴 골짜기 → 벽에 부딪히며 지그재그로 갑니다

그래서 "방향을 안정시키기(모멘텀)", "방향마다 보폭을 따로 정하기(적응형)" 같은 개선이 필요합니다.

### 1-8. 지수이동평균 EMA (슬라이드 14–15)

**평균을 내되, 최근 것을 더 중요하게** 치는 방법입니다.

> m(새) = β · m(옛) + (1−β) · 새 값

β=0.9이면 새 값의 비중 0.1, 한 단계 전 0.09, 두 단계 전 0.081, … 이렇게 **0.9배씩** 작아집니다. 옛날 일은 점점 흐릿하게 기억하는 것과 같습니다.

**손으로 해 보기.** 새 값이 계속 1이고 m은 0에서 시작: 0.1 → 0.19 → 0.271 → … → 1에 가까워짐. (시작을 0으로 해서 처음엔 작게 나옵니다. 2교시의 "편향 보정"이 이것을 고칩니다.)

**비유.** 친구들 키를 평균 내는데 "어제 만난 친구는 크게, 작년에 만난 친구는 작게" 반영하는 평균입니다.

코드 실측: 표준편차 2.07인 잡음 낀 값에 EMA를 적용하면 표준편차가 0.44로 줄었고 평균은 그대로 약 1이었습니다. → EMA는 **잡음은 줄이고 큰 흐름만 남깁니다**.

### 1-9. 모멘텀 = 굴러가는 공 (슬라이드 16–17)

> v ← μ·v + g ,  θ ← θ − η·v   (μ≈0.9)

눈 덮인 비탈에서 공을 굴리면 속도가 붙어서 작은 요철은 그냥 넘어갑니다. 이것이 **관성**입니다.

- 같은 방향으로 계속 → 속도가 쌓여 빨라집니다
- 방향이 +, −, +, −로 흔들리면 서로 상쇄 → 진동이 줄어듭니다

**협곡 실험** (L = ½(x²+100y²), 100걸음, 실측)

| 방법 | 100걸음 뒤 손실 | y 부호가 뒤집힌 횟수(지그재그) |
|---|---|---|
| SGD (η=0.019) | 6.9e-1 | 100번 |
| 모멘텀 (η=0.01, μ=0.9) | 3.1e-4 | 35번 |
| Adam (η=0.3) | 3.2e-4 | — |

SGD는 가파른 방향이 불안정해지지 않게 η를 0.02 아래로 눌러야 해서, 완만한 방향(x)으로는 아주 느립니다. 모멘텀은 이 문제를 크게 줄입니다.

### 1-10. 코드 읽는 법 (`step1_gd_ema.py`, `optim_np.py`)

- `theta = theta - lr * grad` : 식 14.1 그대로
- `m = beta*m + (1-beta)*x` : EMA 한 줄
- `class SGD`: `v *= mu; v += g` 로 속도를 갱신하고 `p -= lr * v` 로 이동. μ=0이면 순수 경사 하강
- 모든 옵티마이저는 `opt.step(params, grads)`로 같은 모양입니다 (파라미터 배열을 **제자리에서** 바꿈)
- `assert`는 "이 값이 맞아야 한다"는 검사입니다. 통과하면 조용히 넘어가고, 틀리면 멈춥니다

**1교시 확인 질문 정답**: Q1 θ = 1 − 0.5×(−2) = 2. Q2 비중 0.5, 0.25, 0.125. Q3 +, −로 흔들리는 기울기가 평균에서 서로 상쇄되기 때문. Q4 학습률이 너무 커서 발산.

## 2교시. Adam과 AdamW

### 2-1. Adam의 두 아이디어 (슬라이드 21)

1. **방향을 부드럽게** (모멘텀): 기울기의 EMA `m`
2. **보폭을 파라미터마다 따로** (적응형): 기울기 제곱의 EMA `v`

> m = β1·m + (1−β1)·g                (식 14.2)
> v = β2·v + (1−β2)·g²               (식 14.3)
> m̂ = m/(1−β1^k), v̂ = v/(1−β2^k)     (편향 보정 ← 원본에 빠져 있음)
> θ ← θ − η · m̂ / (√v̂ + ε)          (식 14.4, 교정)

기본값: β1=0.9, β2=0.999, ε=10⁻⁸. 학습률은 보통 1e-3~3e-4.

### 2-2. m: 방향 (슬라이드 23)

"내가 가던 방향의 90% + 새 기울기의 10%". 같은 방향이 이어지면 점점 커지고, 흔들리면 줄어듭니다. 공이 굴러가는 것과 같은 관성입니다.

### 2-3. v: 크기 (슬라이드 24–25)

`g²`는 부호를 없애고 **얼마나 큰지**만 남깁니다. v는 그 EMA이므로 "이 파라미터의 기울기가 평소 얼마나 큰가"를 나타냅니다. (β2=0.999는 약 1000걸음의 평균)

**왜 절댓값이 아니라 제곱일까?**

- 절댓값 |x|는 0에서 'V'자로 꺾여서 미분이 안 됩니다. 제곱 x²는 'U'자로 매끄럽습니다.
- |x|의 미분은 늘 +1 또는 −1이라 정답 근처에서도 보폭이 안 줄어 왔다 갔다 합니다. x²의 미분은 2x라서 정답에 가까울수록 보폭이 저절로 작아집니다.
- v는 확률에서 말하는 "제곱의 평균(2차 모멘트)"이라는 의미도 있습니다.

(원본은 "수백만 개의 층"이라 제곱이 빠르다고 썼지만, 수백만 개인 것은 층이 아니라 파라미터입니다. 핵심은 **매끄러움**입니다.)

### 2-4. 분모 √v의 마법 (슬라이드 26)

`m̂/√v̂`는 "방향 ÷ 평소 크기"입니다. 기울기가 평소 큰 파라미터는 나눠지는 수가 커서 걸음이 눌리고, 평소 작은 파라미터는 상대적으로 크게 움직입니다.

**실측**: 기울기가 약 10인 파라미터 A와 약 0.1인 파라미터 B를 100걸음 움직였더니

| | A (기울기≈10) | B (기울기≈0.1) |
|---|---|---|
| SGD(η=0.01) | 9.93 | 0.10 |
| Adam(η=0.01) | 1.00 | 0.99 |

SGD는 100배 차이로 움직이지만 Adam은 거의 같은 거리를 갑니다. "모두에게 전용 학습률"이 생긴 셈입니다. 기울기가 일정하면 Adam의 걸음은 **언제나 약 η**입니다.

### 2-5. 편향 보정 — 원본에 빠진 한 줄 (슬라이드 27–28)

m과 v는 0에서 시작하므로 처음엔 진짜 값보다 작게 나옵니다. 특히 v는 (1−β2)=0.001을 곱하니 첫 걸음에 진짜 값의 **1/1000**입니다. 분모가 너무 작아져 첫 걸음이 엄청 커집니다. 그래서 `1−β^k`로 나눠 바로잡습니다. k가 커지면 β^k→0이라 보정은 저절로 사라집니다.

**손계산** (θ=1, g=0.5가 계속, η=0.1)

| | k=1 | k=2 |
|---|---|---|
| m | 0.9×0+0.1×0.5 = 0.05 | 0.9×0.05+0.05 = 0.095 |
| v | 0.001×0.25 = 0.00025 | 0.999×0.00025+0.00025 = 0.00049975 |
| m̂ | 0.05/0.1 = 0.5 | 0.095/0.19 = 0.5 |
| v̂ | 0.00025/0.001 = 0.25 | 0.00049975/0.001999 = 0.25 |
| 이동량 | 0.1×0.5/√0.25 = **0.1** | **0.1** |
| (보정 없이) | 0.316 | 0.425 |

보정 없이는 첫 걸음이 η의 3배 넘게 튑니다.

### 2-6. 코드와 검증 (슬라이드 29–30)

`optim_np.Adam`은 위 식을 한 줄씩 옮긴 것입니다 (`m *= b1; m += (1-b1)*g` 등). 같은 시작값과 같은 기울기 50개를 `torch.optim`에도 넣어 비교했더니 최대 차이가 **1e-15 수준**(컴퓨터의 반올림 오차)이었습니다. 우리 구현이 정확하다는 증거입니다. (SGD+momentum 3.55e-15, Adam 1.11e-16, AdamW 2.22e-16, Adam+L2 5.55e-17)

### 2-7. AdamW: 가중치 감쇠를 따로 (슬라이드 31–33)

**가중치 감쇠**는 가중치가 너무 커지지 않도록 매 걸음 조금씩 줄이는 것입니다. 큰 가중치는 훈련 데이터를 외우기 쉬워서 일반화가 나빠집니다.

SGD에서는 "손실에 λ‖θ‖²/2를 더하는 L2 정규화"와 같습니다. 그런데 **Adam에서는 문제**가 생깁니다. L2 항이 기울기에 섞이면 그 뒤에서 `√v̂`로 나뉘기 때문에, 기울기가 평소 큰 파라미터는 규제가 약해지고 작은 파라미터는 강해집니다. 모두를 같은 비율로 줄이고 싶었는데 뒤죽박죽이 됩니다.

AdamW는 감쇠를 **따로** 합니다. (식 14.5)

> θ ← θ − η · ( m̂/(√v̂+ε) + λ·θ )

**실험** (기울기에 잡음만 있는 파라미터 1000개씩 두 그룹, 잡음 크기 1과 0.01, 500걸음, 감쇠 0.1, 처음 θ=1):

| | 잡음 큰 그룹 | 잡음 작은 그룹 |
|---|---|---|
| Adam + L2 | 0.60 | 0.00 |
| AdamW | 0.60 | 0.61 |

AdamW는 두 그룹이 똑같이 줄어듭니다 ((1−ηλ)^500 = 0.999^500 ≈ 0.606). Adam+L2는 제각각입니다.

PyTorch: `torch.optim.Adam(..., weight_decay=)`는 **L2**, `torch.optim.AdamW(..., weight_decay=)`는 **분리된 감쇠**입니다. 숫자는 같아도 뜻이 다릅니다.

### 2-8. NumPy 신경망으로 직접 학습 (슬라이드 34, `step5_numpy_mlp.py`)

손글씨 숫자(8×8) 1200장 학습, 597장 시험. 은닉 64, 배치 64, 40에포크, 역전파도 NumPy로 직접 구현, 3개 시드 평균.

| 옵티마이저 | 학습률 | 5에포크 학습 손실 | 40에포크 학습 손실 | 시험 정확도 |
|---|---|---|---|---|
| SGD | 0.1 | 0.612 | 0.107 | 96.4% |
| SGD+모멘텀 | 0.05, μ=0.9 | 0.154 | 0.025 | 97.0% |
| Adam | 3e-3 | 0.285 | 0.024 | 97.3% |
| AdamW | 3e-3, wd 0.01 | 0.286 | 0.025 | 97.3% |

작은 데이터라 정확도 차이(약 1%p)가 크지 않습니다. 순위보다 "각 알고리즘이 돌아가는 모습"을 보는 데 의미가 있습니다. 학습률은 옵티마이저마다 따로 잡았습니다.

## 3교시. Lion, Adafactor, 학습률 스케줄

### 3-1. Lion: 크기는 버리고 부호만 (슬라이드 37–38)

2023년 Google이 제안했습니다. "기울기가 +면 한 칸 왼쪽, −면 한 칸 오른쪽"처럼 **방향 부호만** 씁니다.

> c = sign( β1·m + (1−β1)·g )
> θ ← θ − η·( c + λθ )
> m ← β2·m + (1−β2)·g

- 이동량은 항상 η (모든 파라미터가 같은 크기)
- 저장할 상태가 m **하나**뿐 (Adam은 m, v 두 개) → 메모리가 절반
- 논문의 권장: AdamW보다 학습률은 3~10배 작게, 가중치 감쇠는 3~10배 크게

**실측**: 기울기가 ×0.001, ×1, ×1000이어도 첫 걸음은 모두 [0.01 0.01 0.01 0.01]. NumPy 구현과 PyTorch 구현은 30걸음 뒤 차이 1.1e-16으로 일치했습니다. `torch.optim`에는 Lion이 없어서 `torch.optim.Optimizer`를 상속해 직접 만들었습니다 (`step6_torch_compare.py`).

걸음 크기가 늘 η이므로 끝까지 큰 η를 쓰면 바닥에서 흔들립니다 → 학습률을 점점 줄이는 스케줄과 함께 씁니다.

### 3-2. 옵티마이저도 메모리를 먹는다 (슬라이드 39)

| | 파라미터당 추가 숫자 | 70억 파라미터, float32 상태 크기 |
|---|---|---|
| SGD | 0 | 0 |
| SGD+모멘텀 | 1 | 28 GB |
| Adam/AdamW | 2 (m, v) | 56 GB |
| Lion | 1 (m) | 28 GB |
| Adafactor | 행+열만 | 수 MB 이하 |

(70억 × 4바이트 = 28 GB가 가중치 하나의 크기입니다.) 큰 모델에서는 이 차이가 "학습이 되느냐 안 되느냐"를 좌우합니다.

### 3-3. Adafactor: 큰 표를 두 줄로 줄이기 (슬라이드 40–41)

Adam은 v를 가중치 행렬과 **같은 크기**(n×m)로 저장합니다. Adafactor는 v 대신 **행의 합 R**(n개)과 **열의 합 C**(m개)만 저장합니다. 필요하면 `R·Cᵀ / ΣR`로 곱해서 복원합니다.

비유: 구구단 표 전체를 외우는 대신 "가로 숫자 줄"과 "세로 숫자 줄" 두 줄만 외우고, 필요할 때 곱해서 칸 하나를 꺼내는 것입니다. 표가 정말 "가로 규칙 × 세로 규칙"이면 완벽하게 복원되고(실측 오차 2.2e-16), 아니면 근사입니다 (랜덤 행렬 평균 상대 오차 0.54).

**메모리**: n×m → n+m. 4096×4096 행렬이면 16,777,216개 → 8,192개 (2048배 적음). (원본의 "O(n²) → O(n)"은 정사각 행렬일 때만 맞는 말이고, 일반적으로는 O(nm) → O(n+m)입니다.)

우리 구현에는 업데이트가 너무 커지지 않게 RMS로 누르는 클리핑과, 시간에 따라 변하는 β2(t)=1−t^(−0.8)을 넣었습니다 (논문에 나오는 모멘텀과 상대 스텝 크기는 뺀 간단 버전).

### 3-4. 학습률 스케줄 (슬라이드 42–46)

- 초반: 큰 학습률로 빨리 넓게 탐색. 단, 너무 처음부터 크면 불안정하므로 **웜업**(낮게 시작해서 서서히 올림)
- 후반: 작은 학습률로 골짜기 바닥에서 미세 조정

**코사인 감쇠**

> η(t) = η_min + ½(η_max − η_min)(1 + cos(π·t/T))

| t/T | cos | η/η_max (η_min=0) | 선형 감소 |
|---|---|---|---|
| 0 | 1 | 1.000 | 1.000 |
| 0.25 | 0.707 | 0.854 | 0.750 |
| 0.5 | 0 | 0.500 | 0.500 |
| 0.75 | −0.707 | 0.146 | 0.250 |
| 1 | −1 | 0.000 | 0.000 |

시작과 끝에서는 완만하고 중간에서 빠르게 줄어듭니다. 급하게 꺾이는 곳이 없어 안정적입니다. **웜업+코사인**: 처음 100걸음은 직선으로 올렸다가(첫 값 η_max/100) 코사인으로 내립니다. **SGDR(웜 리스타트)**: 주기가 끝나면 학습률을 다시 크게 올려 반복합니다.

용어: 원본은 "Cosine Decay는 한 번만, Annealing은 주기적"이라고 구분했지만 표준적인 구분이 아닙니다. 식은 같습니다. Annealing(담금질)은 금속을 달궈 천천히 식혀 안정시키는 것에서 온 이름입니다.

### 3-5. Sharp vs Flat (슬라이드 47–48)

**Sharp minimum**: 바닥은 깊지만 아주 좁은 골짜기. 파라미터가 조금만 변해도 손실이 확 올라갑니다. **Flat minimum**: 조금 얕지만 넓은 골짜기. 조금 흔들려도 괜찮습니다.

비유: 좁은 병목 끝 깊은 구멍에 공이 들어가 있으면 책상이 살짝만 흔들려도 튀어나오지만, 넓은 그릇 바닥에 있으면 안정적입니다.

**장난감 1차원 실험** (`step4_schedule_sharp.py`)

| | 학습 손실 | 시험 손실(표면 0.25 이동) | 가중치 잡음(σ=0.2) 평균 손실 | 곡률 |
|---|---|---|---|---|
| Sharp (θ=−1.5) | −1.001 | −0.008 | −0.372 | 156.2 |
| Flat (θ=+1.5) | −0.800 | −0.762 | −0.776 | 1.25 |

학습 손실은 sharp가 더 좋지만, 시험 데이터가 조금만 달라지면 이득이 거의 사라집니다. 곡률(2차 미분, Hessian의 큰 고윳값)이 클수록 sharp입니다.

**주의**: "Adam은 sharp로, SGD는 flat으로 간다"는 일부 연구에서 관찰된 **경향**입니다. 법칙이 아니고, 트랜스포머에서는 AdamW가 표준입니다. 일반화는 옵티마이저뿐 아니라 학습률·배치 크기·정규화·스케줄·데이터의 합입니다.

**문제 1. 경사 하강 손계산** L(θ)=(θ−4)², 시작 θ=0, 기울기 2(θ−4).

| η | θ(1) | θ(2) | 판정 |
|---|---|---|---|
| 0.25 | 0−0.25×(−8)=2 | 2−0.25×(−4)=3 | 수렴 (오차에 0.5배씩: 4→2→1) |
| 1.0 | 8 | 0 | 진동 (오차 크기 그대로, 부호만 뒤집힘) |
| 1.1 | 8.8 | −1.76 | 발산 (오차 4, 4.8, 5.76, … 매번 1.2배) |

이차함수에서는 오차에 (1−2η)가 곱해집니다. 0<η<1이면 수렴, η=1이면 진동, η>1이면 발산.

**문제 2. EMA와 편향 보정** m = 0.1, 0.19, 0.271 / m̂ = 0.1/0.1, 0.19/0.19, 0.271/0.271 = **1, 1, 1**. 보정하면 처음부터 진짜 평균(1)이 나옵니다.

**문제 3. 크기가 다른 두 기울기** g=[0.02, −5], η=0.01

- SGD: η·g = (−0.0002, +0.05) → 크기가 25000배 차이
- Adam 첫 걸음: m̂/√v̂ = g/|g| = ±1 → (−0.01, +0.01)
- Lion: sign(g) → (−0.01, +0.01)

둘 다 크기를 무시합니다. (Adam은 이후 걸음에서 과거 크기를 기억하므로 완전히 무시하는 것은 아니고, Lion은 늘 부호만 씁니다.)

**문제 4. 메모리** (a) 1024×4096: Adam v = 4,194,304개, Adafactor R+C = 1024+4096 = 5,120개 → 약 **819배** 적음. (b) 70억 파라미터, float32: Adam 상태 2×28 = **56 GB**, Lion 상태 **28 GB**. (가중치 자체 28 GB는 별도)

**문제 5. 웜업+코사인 구현**

```python
def warmup_cosine_lr(t, T, warm, lr_max):
    if t < warm:
        return lr_max * (t + 1) / warm              # 웜업: 직선 상승

```

## 5. 원본 자료 검토 결과 (오류 검사 및 최신 자료 반영)

원본: `Modern Deep Learning Foundataion 007_Summary.md` (Lesson 14 부분). 아래는 직접 확인하고 고친 목록입니다.

**수식·개념 오류**

1. **Adam 식 14.2~14.4에 편향 보정이 없음** → m̂, v̂ 추가 (PyTorch와 1e-15 수준까지 일치함을 확인).

**설명 과장·표기**

7. "제곱이 절댓값보다 빠르다 / 수백만 개의 층" → 수백만 개는 파라미터. 핵심은 매끄러움.
8. v를 "변동(분산)"으로 설명 → 평균을 빼지 않은 2차 모멘트.
9. "10억 개 이상이면 Adafactor가 사실상 필수" → 과장. 큰 모델도 AdamW로 학습함.
10. Adam 문단의 문장 중복 ("…강건하고 널리 효과적으로 사용하므로, …" 반복).
11. 오타: `θ = theta`, 편형(→편향), 힌다(→한다), 이것인(→이것이), Momemtum, regualaization 등.
12. ∇ 설명에 발산·회전까지 포함 → 틀리진 않지만 학습에는 gradient만 필요하여 정리.

## 6. 이번 자료에서 확인하지 못한 것

- 모든 실험은 **작은 문제**(손글씨 8×8, 파라미터 4,810개)입니다. 옵티마이저 순위를 일반화할 수 없습니다. 대규모 모델에서의 AdamW/Lion/Adafactor 비교는 이 자료에서 직접 돌려 보지 않았고, 논문 설명에 의존합니다.
- NumPy Adafactor는 모멘텀·상대 스텝 크기를 뺀 **간단 버전**이라 `torch.optim.Adafactor`와 수치가 같다고 검증하지 않았습니다 (상태 크기만 비교).
