## 1교시. 모델은 왜 그렇게 답했을까?

### 1-1. 정확하기만 하면 충분할까?

병원에서 의사 선생님이 "검사 결과 위험합니다"라고만 말하면 어떨까요? 무서울 뿐 아니라 믿기도 어렵습니다. "이 수치가 이래서 위험합니다"라고 **이유**를 말해 줘야 수긍이 됩니다.

인공지능도 똑같습니다. 정확도가 99%라도 **이유를 모르면** 믿을 수 없습니다. 그래서 모델이 "왜 그렇게 답했는지" 들여다보는 방법이 필요하고, 이것을 **설명 가능성(Explainability)** 이라고 합니다. 이유는 네 가지입니다.

1. **신뢰**: 사용자가 결과를 믿고 쓸 수 있습니다.
2. **디버깅**: 이상한 동작의 원인을 개발자가 찾습니다.
3. **규제**: 은행·병원은 "왜 이런 판단을 했는지" 설명해야 하는 법적 요구가 있습니다.
4. **공정성**: 모델이 나쁜 단서(예: 사는 동네)에 기대고 있는지 발견합니다.

### 1-2. 왜 딥러닝은 설명하기 어려울까?

- **선형 모델·결정 트리**는 "공부시간이 1시간 늘면 점수 +4점"처럼 숫자를 그대로 읽으면 됩니다. 요리법이 적힌 레시피 같습니다.
- **딥 신경망**은 수백만 개의 숫자가 여러 층에 걸쳐 복잡하게 얽혀 있습니다. "맛은 좋은데 비밀 레시피를 아무도 못 읽는 식당"과 같습니다.

그래서 모델이 완성된 **뒤에** 따로 분석하는 도구들(사후, post-hoc)이 필요합니다. 오늘은 네 가지를 배웁니다.

| 기법 | 알려 주는 것 | 범위 | 모델 |
|---|---|---|---|
| Grad-CAM | 이미지의 어디를 보고 판단했나 | 한 장(국소) | CNN 전용 |
| 순열 중요도 | 특성을 망가뜨리면 성능이 얼마나 떨어지나 | 모델 전체(전역) | 모델 불문 |
| SHAP | 이 한 건의 예측에 각 특성이 얼마나 기여했나 | 한 건(국소) | 모델 불문 |
| 어텐션 가중치 | 단어들이 서로를 얼마나 보나 | 한 문장(국소) | 트랜스포머 |

**국소(local)** = 하나의 예측을 설명, **전역(global)** = 모델이 전반적으로 무엇을 중요하게 보는지.

### 1-3. 사례 연구: 은행의 사기 탐지

은행이 "신용카드 사기 탐지" 인공지능을 만들었습니다. 테스트에서는 정확도가 높았습니다. 그런데 규제 담당자가 "수상한 거래마다 이유를 설명하세요"라고 요구했고, 조사해 보니 **특정 도시 근처에서 정상 거래를 사기로 잘못 판정하는 일**(오탐)이 몰려 있었습니다.

SHAP으로 보니 '거래 위치'가 큰 기여를 하고 있었습니다(특정 가맹점 종류와 함께일 때만). 영수증 사진을 보는 CNN에는 Grad-CAM을 썼더니 거래 내용이 아니라 **형광펜으로 강조된 글자**만 보고 있었습니다. 둘 다 **학습 데이터가 한쪽으로 치우쳤기 때문**이었습니다. 설명 도구 덕분에 재학습과 데이터 개선이 가능했습니다.

핵심 단어는 **지름길(shortcut)** 입니다. 학생이 "정답은 늘 3번이더라"를 외워서 시험을 치르는 것처럼, 모델도 진짜 규칙 대신 쉬운 단서를 배울 수 있습니다. 이 수업에서는 이 상황을 직접 만들어서(Step 4 숫자 '도장', Step 6 가상 은행 데이터) 설명 도구로 찾아냅니다.

### 1-4. Grad-CAM: CNN은 사진의 어디를 봤을까?

#### (1) 준비물 ① 특징 맵(feature map)

CNN은 사진 위를 **작은 손전등(필터)** 으로 훑습니다. '동그란 눈 찾기 손전등'은 눈이 있는 곳에서 환하게 켜집니다. 필터 하나가 훑은 결과를 한 장의 지도로 그린 것이 **특징 맵 A^k** 입니다. k번째 필터면 k번째 지도이고, `A^k_ij`는 그 지도의 (i, j) 칸이 얼마나 환한지입니다.

> **원본 바로잡기**: 교재는 `A^k_ij`를 "(i,j) 위치의 **가중치(weight)**"라고 설명합니다. 하지만 가중치는 학습으로 정해지는 필터 속 숫자들이고, `A`는 사진을 넣을 때마다 **새로 계산되는 반응(활성값, activation)** 입니다. A는 Activation의 A라고 기억하세요. 또 교재 해설의 "가중치 A를 어느 방향으로 돌려야 하는지 결정"이라는 문장도 Grad-CAM은 가중치를 바꾸지 않으므로 맞지 않습니다.

#### (2) 준비물 ② 기울기 = "나사를 살짝 돌렸을 때 전구가 얼마나 밝아지나"

수만 개의 조절 나사가 달린 전구를 상상합시다. 전구 밝기가 `y`, 나사 하나의 위치가 `A`입니다. **나사 하나만** 살짝 돌리고 나머지는 대리석처럼 꼼짝 않게 고정한 채 밝기가 얼마나 변하는지 보는 것이 **편미분** `∂y/∂A` 입니다. 기호 ∂(라운드 디)는 "다른 건 고정하고 이것만"이라는 뜻입니다.

- 분자 `y` = 결과(관심 있는 것), 분모 `A` = 원인(건드려 보는 것)
- `∂y/∂A > 0`: 이 칸이 환해지면 점수가 오른다 → **찬성 증거**
- `∂y/∂A < 0`: 환해지면 점수가 내려간다 → **반대 증거**
- `∂y/∂A ≈ 0`: 상관없다

여기서 `y^c`는 "클래스 c(예: 고양이)에 대한 점수"입니다. 우리는 '고양이' 점수가 어디서 왔는지 알고 싶으므로 다른 클래스는 무시하고 `y^c`만 미분합니다.

#### (3) 식 15.1: 채널(필터)의 중요도 α

$$\alpha_k^c = \frac{1}{Z}\sum_{i}\sum_{j}\frac{\partial y^c}{\partial A^k_{ij}}$$

한마디로 **"지도 k의 모든 칸에서 기울기를 구해 평균 낸 것"** 입니다. `Z = H×W`는 칸의 수이니 그냥 평균입니다. α가 크면 "이 손전등(필터)은 고양이 판정에 중요한 편"입니다.

손계산 (슬라이드 15): 지도 두 장 `A¹ = [[1,0],[2,1]]`, `A² = [[0,2],[1,0]]`. 기울기는 `∂y/∂A¹`가 모든 칸 2, `∂y/∂A²`가 모든 칸 −1이라면

- α¹ = (2+2+2+2)/4 = **2** → 채널 1은 찬성
- α² = (−1−1−1−1)/4 = **−1** → 채널 2는 반대

#### (4) 식 15.2: 가중합 후 ReLU

$$L^c = \mathrm{ReLU}\Big(\sum_k \alpha_k^c A^k\Big)$$

지도들을 α만큼 크게/작게 하여 더합니다. `2·A¹ − 1·A² = [[2,−2],[3,2]]`. 이제 ReLU(음수는 0, 양수는 그대로)를 씌우면 `[[2,0],[3,2]]`. 오른쪽 위 칸은 "고양이가 아니라는 증거"가 더 세서 꺼졌습니다. 남은 밝은 곳이 "고양이라고 판단한 근거 영역"입니다. 마지막에 사진 크기로 키워서(업샘플링) 원본 위에 겹쳐 그립니다.

> **원본 바로잡기**: 교재 그림 15.2의 설명은 "음의 값은 ReLU에 의해 제거"라고 되어 있어 *음수 α를 가진 채널이 사라지는* 것처럼 읽힙니다. 실제로는 **합친 결과의 칸별 값**에 ReLU가 적용됩니다. 위 예에서 α²=−1인 채널도 합에는 들어가서 값을 깎고(−1·A²), 합이 음수가 된 칸만 0이 됩니다. 식 15.2의 이름 `L_c^{Grad-GAM}`은 `Grad-CAM`의 오타입니다.

#### (5) Grad-CAM 5단계

1. 순전파: 사진을 넣어 마지막 합성곱 층의 지도 A와 점수 y^c를 얻는다
2. 역전파: y^c에서 A까지 거슬러 올라가 `∂y^c/∂A`를 얻는다
3. 채널마다 기울기를 평균 → α (식 15.1)
4. 가중합 + ReLU (식 15.2)
5. 사진 크기로 키워서 원본 위에 겹친다

마지막 합성곱 층을 쓰는 이유: 그 층은 **의미는 높은데 아직 위치 정보가 남아 있는** 층이기 때문입니다. 그 뒤 완전연결층부터는 위치 정보가 사라집니다.

#### (6) Step 3 코드: 손으로 만든 CNN (`step3_gradcam_numpy.py`)

정답을 우리가 알고 있어야 코드가 맞는지 확인할 수 있으므로 가중치를 학습하지 않고 **손으로** 정했습니다.

- 10×10 그림에 십자(+, 왼쪽 위), X(오른쪽 위), 네모(오른쪽 아래)를 그렸습니다.
- 필터 3개가 각각 십자/네모/X에서만 크게 반응하도록 숫자를 정했고, 약한 반응은 편향으로 ReLU가 끄게 했습니다.
- 클래스 0 = "십자가 있다", 클래스 1 = "네모가 있다". 클래스 0에게 X는 **반대 증거**(가중치 −1)입니다.

핵심 함수:

```python
alpha = g.mean(axis=(1, 2))            # 식 15.1: 채널별 기울기의 공간 평균
s = np.tensordot(alpha, A, axes=1)     # Σ α_k A^k
cam = np.maximum(s, 0)                 # 식 15.2: ReLU
```

**기울기 검사**: 손으로 한 미분이 맞는지, 값을 아주 조금(±1e-5) 흔들어 계산하는 수치 미분과 비교합니다. 최대 오차가 9.5×10⁻¹²여서 통과입니다. 미분을 직접 짠 코드에는 항상 이 검사를 하는 습관을 들이세요.

결과: 클래스 0의 히트맵 최대는 (2,2) = 십자 중심, 클래스 1은 (7,7) = 네모 중심이었습니다. X가 있던 곳은 ReLU 전 값이 −0.75(반대 증거)였다가 ReLU 후 0이 됩니다. α = (0.25, 0, −0.25).

#### (7) Step 4 코드: PyTorch hook과 '도장' 실험 (`step4_gradcam_torch.py`)

**hook**은 순전파·역전파 도중에 끼워 두는 감시 장치입니다. 모델 코드를 고치지 않고 중간 값을 훔쳐볼 수 있습니다.

```python
def fwd_hook(module, inp, out):
    store['A'] = out                                   # ① 지도 A 저장
    out.register_hook(lambda g: store.update(g=g))     # ② 나중에 기울기가 돌아오면 저장
h = net.relu3.register_forward_hook(fwd_hook)
out = net(x); h.remove()
out[0, c].backward()                                   # ③ y^c에서 역전파 → store['g'] = ∂y^c/∂A
```

이어서 `alpha = g.mean(dim=(2,3))`, `cam = relu((alpha*A).sum(1))`로 NumPy 버전과 똑같이 계산하고, 보기 좋게 입력 크기로 키웁니다.

**실험 설계**: 손글씨 숫자(16×16, 약한 잡음)로 모델 둘을 학습합니다. 정상 모델은 그대로, 지름길 모델은 학습 데이터에서 **7에만** 왼쪽 위에 4×4 밝은 '도장'을 찍어서 학습합니다. 도장이 정답 7과 늘 같이 다니니 모델은 숫자 모양 대신 도장을 배울 수 있습니다(영수증의 강조 글자와 같은 구조).

결과 (시드 0, 한 번의 학습):

| 측정 | 정상 모델 | 지름길 모델 |
|---|---|---|
| 깨끗한 테스트 정확도 | 0.84 | 0.80 |
| 7이 아닌 숫자에 도장을 찍었을 때 7로 오답 | 5.7% | **47.7%** |
| Grad-CAM 에너지 중 왼쪽 위 1/4 구역 몫 (면적 25%) | 0.33 | **0.55** |

깨끗한 정확도는 0.84와 0.80으로 큰 차이가 없어서 **눈치채기 어렵지만**, 도장을 찍으면 약 절반이 7로 오답이 되고, 히트맵도 도장 쪽으로 쏠립니다. 이것이 사례 속 "테스트에서는 높은 정확도"와 같은 상황입니다.

> 정직한 메모: 히트맵은 해상도가 낮습니다(8×8 지도를 키운 것). 그래서 붉은 영역이 도장 '바로 아래'에 나타납니다. Grad-CAM은 가설을 만드는 도구이고, 확인은 도장을 지워 보는 개입 실험으로 합니다.

**보너스: Integrated Gradients** (교재 범위 밖). 검은 기준 이미지에서 입력까지 직선으로 걸으며 기울기를 평균하는 방법입니다. 속성의 합이 `f(x) − f(기준)`이 되어야 한다는 "완전성"을 코드로 확인합니다(99.613 vs 99.796, 가까움). Grad-CAM++는 같은 물체가 여러 곳에 있을 때 Grad-CAM을 개선한 방법입니다.

#### 1교시 확인 질문 답

- Q1 α가 음수인 채널 → 그 채널이 켜진 칸의 합을 낮춘다(반대 증거). 합이 음수가 되면 ReLU가 지운다.
- Q2 마지막 합성곱 층 → 위치 정보가 남아 있으면서 의미가 높기 때문.
- Q3 히트맵이 도장을 가리키면 → 데이터를 점검하고(도장 제거·섞기) 재학습.

## 2교시. 중요도와 샤플리 값

### 2-1. 순열 중요도: "망가뜨려 보면 안다"

팀 프로젝트에서 누가 제일 중요한지 알고 싶으면, 한 명의 일을 엉뚱하게 바꿔 놓고 성적이 얼마나 떨어지는지 봅니다. 많이 떨어지면 중요한 사람입니다. 모델의 **특성(열) 하나의 값을 무작위로 섞으면** 그 특성과 정답의 관계가 끊깁니다. 이때 성능이 얼마나 떨어지는지가 그 특성의 중요도입니다.

$$\Delta_i = M_0 - M_i \quad (\text{식 15.3})$$

`M_0`는 원래 점수, `M_i`는 `i`번 특성을 섞은 뒤의 점수입니다.

손계산 (슬라이드 29): 모델은 "공부시간 ≥ 5이면 합격"입니다. 학생 5명의 공부시간 `[8,6,2,7,1]`을 섞어 `[2,7,1,8,6]`이 되면 예측이 `[0,1,0,1,1]`, 정답 `[1,1,0,1,0]`이라 3명만 맞습니다. 그래서 `M_0 = 5/5 = 1.0`, `M_공부 = 3/5 = 0.6`, `Δ_공부 = 0.4`. 키 열은 모델이 보지 않으니 섞어도 `Δ_키 = 0`입니다. 섞는 방식에 따라 값이 흔들리므로 20번 반복해 평균을 냅니다.

#### Step 1 코드 (`step1_permutation.py`)

```python
M0 = accuracy(w, b, X, y)                     # 기준 성능
for i in range(X.shape[1]):                   # 특성마다
    for _ in range(repeats):                  # 여러 번 섞어 보기
        Xp = X.copy()                         # 원본은 그대로 두고
        Xp[:, i] = rng.permutation(Xp[:, i])  # i번째 열만 섞기
        d.append(M0 - accuracy(w, b, Xp, y))  # Δ_i = M0 − M_i
```

데이터: 합격은 `공부시간(강) > 출석률(중) > 수면(약) > 키(무관)` 순서로 영향을 받도록 만들었고, 모델은 NumPy로 학습한 로지스틱 회귀입니다.

결과: 기준 정확도 `M_0 = 0.883`. Δ(공부시간)=0.312±0.009, Δ(출석률)=0.118±0.008, Δ(수면)=0.015±0.005, Δ(키)=0.000. **중요도 순서가 진짜 규칙과 같습니다.**

**함정 (슬라이드 32, 33)**: 공부시간의 거의 복사본인 열을 하나 더 붙이면 중요도가 둘로 쪼개져 둘 다 0.12 정도로 작아 보입니다(공부시간 0.124, 복사본 0.117). 섞어도 다른 쪽이 같은 정보를 들고 있기 때문입니다. 그리고 데이터를 섞으면 "키 120cm인데 체중 100kg" 같은 현실에 없는 조합이 생길 수 있고, **어떤 데이터로 재는지**에 따라 결론이 달라집니다(3교시 사기 탐지 사례에서 직접 확인).

### 2-2. SHAP: 샤플리 값 = "공정한 상금 나누기"

세 명이 같이 일해서 상금 11만 원을 받았습니다. 누가 얼마나 기여했을까요? 혼자 했을 때, 둘이 했을 때, 셋이 했을 때 성과가 다릅니다. 가장 공정한 방법은 **"모든 순서로 한 명씩 합류해 보면서, 각자가 들어올 때 늘어난 몫을 평균"** 내는 것입니다. 이것이 게임 이론의 **샤플리 값**이고, 이것을 모델 예측에 적용한 것이 **SHAP**입니다. 플레이어 = 입력 특성, 상금 = 모델 출력입니다.

#### 손계산 (슬라이드 35~36)

`f(x) = 2·x1 + 3·x2 + x1·x3`, `x = (1,2,3)`, 기준 = (0,0,0). 특성을 '켜면' 진짜 값, '끄면' 기준값 0으로 두고 f를 계산합니다.

| 켠 특성 | ∅ | {1} | {2} | {3} | {1,2} | {1,3} | {2,3} | {1,2,3} |
|---|---|---|---|---|---|---|---|---|
| f | 0 | 2 | 6 | 0 | 8 | 5 | 6 | 11 |

합류 순서 3! = 6가지에서 각 특성이 더한 몫:

| 순서 | 특성1 | 특성2 | 특성3 |
|---|---|---|---|
| 1→2→3 | 2 | 6 | 3 |
| 1→3→2 | 2 | 6 | 3 |
| 2→1→3 | 2 | 6 | 3 |
| 2→3→1 | 5 | 6 | 0 |
| 3→1→2 | 5 | 6 | 0 |
| 3→2→1 | 5 | 6 | 0 |
| **평균 φ** | **3.5** | **6.0** | **1.5** |

합 = 3.5 + 6 + 1.5 = 11 = f(전체) − f(∅). 몫을 **남김없이** 나눴습니다(효율성). 특성 1과 3은 곱(`x1·x3 = 3`)으로 엮여 있어서 그 몫 3을 평균하면 둘이 공평하게 1.5씩 가집니다.

#### 식 15.4 풀어 읽기

$$\phi_i = \sum_{S\subseteq F\setminus\{i\}}\frac{|S|!\,(|F|-|S|-1)!}{|F|!}\,\big[f(S\cup\{i\})-f(S)\big]$$

- `F`: 전체 특성의 집합, 예: `F = {1,2,3}`.
- `F∖{i}`: F에서 i를 뺀 것. i=1이면 `{2,3}`.
- `S ⊆ F∖{i}`: 그 중 만들 수 있는 모든 부분집합. `{2,3}`이면 `∅`(공집합), `{2}`, `{3}`, `{2,3}`.
- `f(S∪{i}) − f(S)`: S에 i가 새로 들어왔을 때의 이득. i가 이미 S에 있으면 "더한다"는 말이 안 되므로 **i를 제외**합니다.
- 앞의 분수는 **"S가 먼저 모이고 바로 다음에 i가 들어오는 순서"가 6가지(=|F|!) 중 몇 가지인가**입니다.

특성 1에 대해 (슬라이드 38):

| S | 가중치 | 이득 | 가중치×이득 |
|---|---|---|---|
| ∅ | 1/3 | 2−0=2 | 0.667 |
| {2} | 1/6 | 8−6=2 | 0.333 |
| {3} | 1/6 | 5−0=5 | 0.833 |
| {2,3} | 1/3 | 11−6=5 | 1.667 |
| 합 | 1 | | **3.5** |

6가지 순서를 직접 평균한 것(3.5)과 같은 값입니다. 부분집합 식은 같은 계산을 묶어 쓴 것입니다.

#### 샤플리 값의 네 가지 공리

1. **효율성**: 기여도의 합 = f(전체) − f(∅)
2. **대칭성**: 똑같이 기여하는 두 특성은 같은 값
3. **더미**: 아무 영향 없는 특성은 0
4. **가산성**: 두 모델의 합에 대한 설명 = 각 설명의 합

이 네 가지를 모두 만족하는 분배는 샤플리 값뿐입니다. 그래서 "공정한 설명"의 근거가 됩니다.

#### f(S)는 어떻게 구하나?

모델은 모든 특성을 다 받아야 계산됩니다. 그래서 **모르는 특성을 기준값(평균 등)으로 바꿔 넣고** 돌립니다(Step 2). 기준이 달라지면 φ도 달라지므로 "무엇과 비교해서" 쪼갰는지 밝혀야 합니다. 더 정확하게는 기준값을 여러 개 바꿔 넣고 출력의 평균(기댓값)을 씁니다.

#### Step 2 코드 (`step2_shap.py`)

```python
masks = (np.arange(2**n)[:, None] >> np.arange(n)) & 1  # 000~111 비트표: 어떤 특성을 켤까
X = np.where(masks == 1, x, base)                       # 켠 것=진짜값, 끈 것=기준값
v = f(X)                                                # 모든 부분집합의 f(S)를 한 번에
...
wgt = factorial(k) * factorial(n-k-1) / factorial(n)    # 가중치 (k = |S|)
phi[i] += wgt * (v[mask | 1<<i] - v[mask])              # 식 15.4
```

- 부분집합을 **0/1 비트**로 표현합니다(3개면 000~111, 8가지).
- `S에 i가 있으면 건너뜀`(`if mask >> i & 1: continue`).
- 마지막에 효율성 `Σφ == f(전체) − f(∅)`를 assert로 확인합니다.
- PyTorch 버전(`shapley_torch`)은 같은 마스크 표를 텐서로 만들어 모델에 한꺼번에 넣고, NumPy와 값이 같은지 확인합니다.

결과: 위 손계산 예에서 `φ = [3.5, 6.0, 1.5]`. 학습된 합격 모델로 학생 1명을 설명하면 평균 학생 로짓 0.07 → 이 학생 5.95이고 φ(공부시간)=+6.21, φ(출석률)=−1.01, φ(수면)=+0.68, φ(키)=+0.00. 합 5.881 = 5.95 − 0.07 ✔. 선형 모델이라서 `φ_i = w_i·(x_i − 평균_i)`와도 같습니다 ✔.

#### 비용: 2^n의 벽

| 특성 수 n | 8 | 12 | 16 | 18 | 30 |
|---|---|---|---|---|---|
| 부분집합 수 | 256 | 4,096 | 65,536 | 262,144 | 약 10억 |
| 측정 시간 | 0.00초 | 0.01초 | 0.30초 | 1.49초 | (추정) 수 시간 이상 |

그래서 현실에서는 근사를 씁니다. **Kernel SHAP**(모델 불문, 부분집합을 일부만 뽑아 가중 회귀), **Deep SHAP**(신경망용, 역전파 규칙으로 전파), 그리고 우리가 만든 **무작위 순서 표본**(무작위 순서로 켜 보며 평균). 순서 표본 수에 따른 최대 오차(n=4 측정): 5개 0.038, 20개 0.106, 100개 0.0065, 1000개 0.0039. 표본이 적으면 들쭉날쭉하고 많을수록 정확합니다.

#### 2교시 확인 질문 답

- Q1 특성 4개일 때 i를 뺀 3개의 부분집합 → 2³ = 8개, 가중치 합 1.
- Q2 같은 정보를 가진 두 열 → 순열 중요도는 둘 다 작아 보이고, SHAP은 대칭성에 따라 두 열이 같은 몫을 나눠 갖는다.
- Q3 합이 f(전체) − f(∅)인 이유 → 모든 순서에서 이득을 다 더하면 항상 그 값이 되기 때문(효율성).

## 3교시. 어텐션, 종합 사례, 한계

### 3-1. 어텐션 가중치로 텍스트 설명

트랜스포머는 문장에서 각 단어가 **다른 단어를 얼마나 쳐다볼지** 계산합니다. 교실에서 "그것(it)"이라는 말을 들으면 모두가 "그게 뭐지?" 하고 앞에서 나온 단어들을 둘러보는 것과 같습니다.

$$\mathrm{Attention}(i,j)=\frac{\exp(q_i\cdot k_j/\sqrt{d_k})}{\sum_{j'}\exp(q_i\cdot k_{j'}/\sqrt{d_k})}\quad(\text{식 15.5})$$

- `q_i`: 단어 i가 **찾는 것**(쿼리), `k_j`: 단어 j가 **내세우는 것**(키)
- `q·k`: 얼마나 맞는가(내적 = 닮은 정도)
- `/√d_k`: 점수가 너무 커지지 않게 하는 크기 보정
- softmax(`exp / Σexp`): 점수를 비율로 바꿔 **한 행의 합이 1**이 되게 함
- 이 가중치들을 모은 표가 `T×T` 행렬 A (i행 j열 = i가 j를 보는 정도)

손계산 (슬라이드 48): `q=(2,0)`, `k1=(1,0)`, `k2=(0,1)`, `d_k=2`. 내적 2, 0 → √2로 나눔 1.414, 0 → exp 4.11, 1 → 합 5.11로 나눔 → **(0.80, 0.20)**. q가 토큰 1과 같은 방향이라 80%를 쏟습니다.

#### Step 5 코드 (`step5_attention.py`)

문장 *"The animal didn't cross the street because it was too tired"* (11 토큰)에 손으로 설계한 가중치를 줍니다(대명사 it은 '동물'을 찾는다).

```python
S = Q @ K.T / np.sqrt(d)       # 점수 q·k/√d
A = softmax(S)                 # 각 행의 합 = 1 (식 15.5)
return A, A @ V                # 가중치, 출력
...
np.linalg.norm(A[i][:, None] * V, axis=1)   # 기여: 토큰 j의 값만 가렸을 때 출력 변화 ‖A_ij·v_j‖
```

마지막에는 PyTorch `nn.MultiheadAttention`에 같은 [Wq;Wk;Wv]를 넣으면 같은 가중치·출력이 나옴(`True`)을 확인합니다.

결과: **"it"이 animal을 0.60으로 가장 크게 봅니다**(대명사 참조 해결). 그런데 문장 첫 단어 **"The"** 가 0.19로 둘째입니다. 이 토큰의 값(v)은 0벡터라서 출력에는 기여가 **0.00**입니다. 모든 단어가 첫 토큰을 조금씩 쳐다보는 이 현상을 **어텐션 싱크**라고 합니다. 어텐션 순위와 기여 순위의 상관은 0.56으로 "같지 않습니다". 즉 **많이 본다 ≠ 많이 기여한다**. 출력에서 토큰 j의 몫은 `A_ij`(얼마나 봤나)와 `v_j`(무엇을 가져왔나)의 곱이기 때문입니다.

(참고: 토큰을 문장에서 *아예 빼고* 다시 계산하면 남은 토큰들의 가중치가 다시 커져서 "The"를 빼도 출력이 0.14 변합니다. 어떻게 기여를 재느냐도 선택입니다.)

#### 어텐션은 설명일까?

교재는 "인과가 아니라 연관성"이라고 경고합니다. 학계에서도 논쟁이 있습니다(교재 범위 밖): Jain & Wallace(2019) "Attention is not Explanation", 이에 대한 Wiegreffe & Pinter(2019)의 반론, Kobayashi 등(2020)의 "가중치만이 아니라 값 벡터 크기도 보라". 실무 규칙은 **어텐션 히트맵은 가설을 세우는 단서로 쓰고, 중요도 주장은 다른 방법으로 교차 확인**하는 것입니다. (논문 이름·연도는 일반적으로 알려진 것을 적었으니 수업 전에 한 번 더 확인하세요.)

### 3-2. 종합 사례: 사기 탐지 모델 감사 (`step6_fraud_case.py`)

가상 은행 데이터를 만듭니다. 특성 6개: 금액, 야간, 집과의 거리, 온라인 가맹점, **도시A**, 24시간 거래수. **진짜 사기 규칙에는 도시A가 없습니다.** 그런데 학습·검증 데이터는 '감사로 모은 표본'이라 사기이면서 온라인이면 92%가 도시A(정상은 12%)입니다. 현장 데이터에서는 도시A가 15%로 사기와 무관합니다. 모델은 NumPy로 손수 역전파를 짠 6→8→1 신경망입니다.

**① 오탐은 어디에 몰릴까** — 검증 AUC는 0.921이라 훌륭해 보이지만 현장 AUC는 0.807입니다. 정상 거래의 오탐률: 전체 10%, 도시A 아님 5%, **도시A 34%**, **도시A & 온라인 51%**.

**② 전역 중요도 (순열)** — 개발팀이 가진 검증 데이터로 재면 금액 0.159, **도시A 0.113**(2위), 집과의 거리 0.054, 온라인 0.033 … 도시A가 2위입니다. 그런데 현장 데이터에서 재면 도시A는 0.003입니다. 현장에서는 도시A와 사기가 무관해서 도시A를 섞어도 AUC가 거의 변하지 않기 때문입니다. **같은 도구도 어떤 데이터에 쓰느냐에 따라 결론이 달라집니다.**

**③ 오탐 한 건의 SHAP** — 거래 #101: 기준 사기확률 0.16 → 이 거래 0.52(합 0.355 = 0.52 − 0.16 ✔). 도시A +0.389, 금액 −0.229, 야간 +0.174, 온라인 +0.109. 오탐 50건 평균에서도 도시A +0.42, 온라인 +0.12가 압도적입니다. 모델은 도시A와 온라인 조합을 의심 신호로 읽고 있었습니다.

**조치**: 도시A 열을 빼고 재학습하면 현장 AUC 0.807 → 0.868, 도시A 정상 거래의 오탐률 34.1% → 11.7%. 열을 빼는 것은 임시 처방이고, 근본 해결은 표본을 모으는 방식을 고치는 것입니다.

### 3-3. 한계와 해석 가능성의 트레이드오프

| 기법 | 한계 | 잘못 읽기 쉬운 곳 |
|---|---|---|
| Grad-CAM | 해상도가 낮고 깊은 층에서 노이즈 | '봤다'를 '근거로 삼았다'로 읽음 |
| SHAP | 특성 상관이 있으면 불안정, 계산 비용 큼 | 교란 변수의 대리 변수에 높은 값 → 원인으로 오해 |
| 순열 중요도 | 상관된 특성·비현실적 조합에 약함 | 어떤 데이터로 쟀는지 잊음 |
| 어텐션 | 연관성이지 인과가 아님, 층·헤드마다 일관성 없음 | 문법 토큰을 의미로 오해 |

설명 가능성은 절대적 진리가 아니라 **진단을 위한 관점**입니다. 도메인 지식, 강건성 검증(도장 지우기 같은 개입 실험), 사람의 평가와 함께 써야 의미가 있습니다.

### 3-4. 어떤 방법을 고를까?

| 상황 | 먼저 쓸 방법 |
|---|---|
| CNN이 이미지의 어디를 보는지 | Grad-CAM (필요하면 Integrated Gradients) |
| 표 데이터에서 전반적인 중요도 | 순열 중요도 |
| 한 건의 예측 이유(규제 대응) | SHAP |
| 트랜스포머 토큰 관계 | 어텐션 + 값 가려 보기/기울기 교차 검증 |
| 특성이 아주 많은데 SHAP이 필요 | Kernel/Deep SHAP, 샘플링 근사 |

한 방법만 믿지 말고 **서로 다른 두 방법으로 교차 확인**하세요. 오늘의 교훈: **높은 정확도 ≠ 올바른 이유**.

## 4. 실습 문제 풀이 (`practice_solutions.py`)

모든 풀이는 코드로 검증됩니다(`python practice_solutions.py` → "모든 풀이가 맞습니다 ✔").

**문제 1. 샤플리 값 손계산.** `f = 3·x1 + 2·x2 + x1·x2`, `x=(2,1)`, 기준 (0,0).
`f(∅)=0, f({1})=6, f({2})=2, f({1,2})=10`. 특성이 2개면 순서가 2가지라 가중치가 모두 ½.
`φ1 = ½·6 + ½·(10−2) = 7`, `φ2 = ½·2 + ½·(10−6) = 3`. 합 10 = f(x) − f(기준) ✔. 곱 항 `x1·x2 = 2`는 두 특성이 1씩 나눠 가집니다.

**문제 2. 순열 중요도.** 모델이 x1만 쓰면 `Δ1 = 0.504`(정확도가 거의 절반으로), `Δ2 = 0.000`(섞어도 예측이 전혀 안 변함). 순열 중요도는 데이터 속 진짜 관계가 아니라 **모델이 실제로 쓴 정도**를 잽니다.

**문제 3. Grad-CAM 손계산.** `α¹=2`, `α²=−1`, `Σα·A = [[2,−2],[3,2]]`, ReLU 후 `L = [[2,0],[3,2]]`. α²가 음수인 채널은 사라지는 게 아니라 합에서 값을 깎고, 칸별 합이 음수일 때만 ReLU가 지웁니다.

**문제 4. 어텐션 한 줄.** `q·k = 2, 0, 1` → `/√2 = 1.414, 0, 0.707` → exp `4.11, 1, 2.03` (합 7.14) → 가중치 **(0.58, 0.14, 0.28)**. 출력 `o = 0.58·(1,0) + 0.14·(0,0) + 0.28·(0,1) = (0.58, 0.28)`. (c) v2=(0,0)이라 가중치 0.14를 받아도 가져오는 내용이 없어 기여 0 → 많이 본다 ≠ 많이 기여한다.

**문제 5. SHAP 공리 확인.** `f = sin(x1)·x2 + x3²`(x4는 미사용). `φ = [1.052, 0.631, 2.250, 0.000]`, 합 3.933 = f(x) − f(기준) (효율성 ✔), `φ4 = 0`(더미 ✔).
