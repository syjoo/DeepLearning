# 1회차 · 1교시 — 글자를 숫자로 바꾸기

## 슬라이드 1. 표지 — Transformer 입문

* 제목: "기초 개념부터 NumPy · PyTorch 직접 구현까지". 즉 **개념 → 손으로 만들기(NumPy) → 실전 도구로 만들기(PyTorch)** 순서로 갑니다.
* "ChatGPT의 심장을 처음부터 끝까지 내 손으로 만들어 봅니다"의 **심장**이 바로 트랜스포머(Transformer)입니다.
* 그림의 "나는 / AI를 / 배운다 → [0.2, -1.1, 0.7, ...]"은 오늘 첫 번째 마법을 보여 줍니다. **글이 숫자 묶음으로 바뀝니다.**

💡 **비유**: 트랜스포머는 자동차의 엔진입니다. 우리는 엔진을 사 오지 않고 부품부터 직접 깎아서 조립해 볼 거예요. 그러면 ChatGPT가 왜 움직이는지 알게 됩니다.



## 슬라이드 2. 강의 로드맵 — 6교시

* 강의는 **2번(회차) × 3시간 = 6교시**입니다. 한 교시는 50분 수업 + 10분 쉬는 시간.
* 표를 풀어 읽으면:
  * **1교시**: 글자를 숫자로 바꾸는 법(토큰화·임베딩) + 트랜스포머 전체 모습 → 직접 만드는 것: *Step 1*
  * **2교시**: 단어 순서(위치 인코딩), 어텐션(Q·K·V), softmax, 마스크 → *Step 2~3*
  * **3교시**: 멀티헤드, FFN, 잔차연결, LayerNorm, 블록 조립 → *Step 4*
  * **4교시**: 모델이 *공부하는 방법* (손실, 역전파, 자동미분) → *Step 5*
  * **5교시**: NumPy만으로 GPT를 만들어 학습시키고 글 쓰게 하기 → *Step 6*
  * **6교시**: PyTorch로 실전 버전 만들기 + 검증 + 실습 문제
* 준비물: Python, NumPy(숫자 계산 도구 모음), 6교시엔 PyTorch(딥러닝 도구 모음).

💡 **비유**: 레고 설명서의 목차입니다. 1~3교시는 부품 만들기, 4교시는 "공부시키는 법", 5~6교시는 완성하고 비교하기.



## 슬라이드 3. 목표 — 이 강의가 끝나면 할 수 있는 일

네 가지 목표입니다.

1. **설명하기**: "글자가 숫자가 되고 → 어텐션을 거쳐 → 다음 글자를 맞히는" 흐름을 내 말로 이야기할 수 있다.
2. **계산하기**: 어텐션의 비율을 손으로 계산하고, 숫자 표의 크기(shape)를 따라갈 수 있다.
3. **만들기 (NumPy)**: 도구 없이 처음부터 만든다. "공부하는 장치"(자동미분)까지 직접!
4. **만들기 (PyTorch)**: 같은 걸 전문가 도구로 만들고, 내 것과 도구의 것이 같은 결과를 내는지 확인한다.

## 슬라이드 4. 1교시 시작

* 출발점은 한 문장: **"컴퓨터는 숫자만 이해한다."** 오늘 수업 전체의 첫 번째 열쇠입니다.



## 슬라이드 5. 컴퓨터는 글자를 모른다, 숫자만 안다

* 신경망(인공지능의 뇌)이 하는 일은 사실 **곱하기와 더하기**뿐입니다.
* 그런데 글자 "사과"를 어떻게 곱할 수 있을까요? 못 합니다. 그래서 **번역**이 필요합니다.
* 해결책은 **두 단계 변환**입니다.
  1. **토큰화**: 글자를 → 정수 번호로 (예: "사" → 17번)
  2. **임베딩**: 번호를 → 숫자 묶음(벡터)으로 (예: 17번 → `[0.2, -1.1, 0.7, ...]`)
* 이 두 단계는 ChatGPT를 포함한 **모든 언어 모델의 출발점**입니다.

💡 **비유**: 외국인 친구와 대화하려면 통역사가 필요하죠? 컴퓨터는 "숫자 나라" 사람이라서, 글자를 숫자로 통역해 주는 과정이 먼저 필요합니다.



## 슬라이드 6. ① 토큰화 — 문장을 조각내어 번호 붙이기

* **토큰** = 모델이 다루는 가장 작은 조각. 자르는 방법이 세 가지입니다.

| 방식 | 예 | 장점 / 단점 |
| --- | --- | --- |
| 문자 단위 | h · e · l · l · o | 단순하고 목록이 작다. 오늘 실습에서 사용 |
| 단어 단위 | I · love · AI | 이해하기 쉽지만 단어가 너무 많아 목록이 어마어마하게 커진다 |
| 서브워드(BPE) | un · believ · able | 단어를 의미 있는 조각으로 자름. ChatGPT 등 실제 모델이 사용 |

* 핵심 문장: **"번호는 단지 이름표일 뿐, 크기에 의미가 없다."**
  * 3번이 1번보다 "세 배 크다"거나 "더 중요하다"는 뜻이 아닙니다. 학번이나 사물함 번호 같은 것이에요.

💡 **비유**: 레고를 블록 하나씩(문자), 완성된 모형 통째로(단어), 또는 자주 쓰는 덩어리(서브워드)로 나눠 상자에 담는 것과 같습니다. 서브워드는 처음 보는 단어도 "아는 조각"으로 쪼개서 표현할 수 있어서 똑똑한 방법입니다.



## 슬라이드 7. 어휘집(vocab)과 인코딩 / 디코딩

예: 텍스트 `"hello"`

1. 쓰인 글자를 모읍니다 → h, e, l, o (중복 제거)
2. 사전순으로 정렬합니다 → e, h, l, o
3. 순서대로 번호를 붙입니다 → **e=0, h=1, l=2, o=3**
4. 이 대응표가 **어휘집(vocab)**입니다.

* **인코딩(encode)**: 글 → 번호. `"hello"` → `[1, 0, 2, 2, 3]`
* **디코딩(decode)**: 번호 → 글. `[1,0,2,2,3]` → `"hello"`
* 두 개의 사전
  * `stoi` (string to int): 글자 → 번호. 학습할 때(글을 모델에 넣을 때) 사용
  * `itos` (int to string): 번호 → 글자. 모델이 글을 만들어 낼 때(숫자를 글로 되돌릴 때) 사용
* **vocab_size(어휘 크기, V)** = 서로 다른 토큰의 개수. 여기선 4개. 모델의 마지막 출력은 "V개 중 다음 토큰은 무엇일까?"를 맞히는 문제가 됩니다. (ChatGPT류는 수만~수십만 개)

💡 **비유**: 반 친구들에게 출석번호를 붙여 주는 일과 같습니다. 번호로 부르는 사전(stoi)과, 번호를 듣고 이름을 찾는 사전(itos) 두 개가 있는 거예요.



## 슬라이드 8. ② 임베딩 — 번호를 의미 있는 숫자 벡터로

* 번호 3은 그냥 이름표라서 "3번이 어떤 글자인지" 성격을 알려 주지 못합니다. 그래서 토큰마다 **성격을 나타내는 숫자 묶음(벡터)**을 하나씩 줍니다.
* 표(E)는 세로 V줄(토큰 개수) × 가로 d_model칸(벡터 길이)입니다. 슬라이드의 표는 4칸짜리 예시예요.
* **조회**: 2번 토큰이 필요하면 표의 2번 행을 꺼내면 끝. 수식으로는 `E[번호]`.
* 처음에는 **랜덤 값**이지만, 공부(학습)를 하면서 값이 조금씩 바뀌어 **의미가 담깁니다.**
* `d_model`은 벡터의 길이입니다. GPT-3는 12,288칸! 우리는 8~64칸을 씁니다.

**알아 두기 해설**

* 임베딩 표는 "학습되는 파라미터"입니다. 모델이 공부하며 계속 고쳐 가는 숫자예요.
* "one-hot 벡터 × 표" 행렬곱과 같은 결과인데, 그냥 행을 꺼내는 편이 훨씬 빠릅니다. (one-hot: 해당 번호만 1, 나머지는 0인 벡터)
* 같은 토큰은 위치와 상관없이 처음엔 **같은 벡터**를 받습니다. 위치 정보는 2교시에서 따로 더합니다.
* 결과 모양(shape) = `(T, d_model)`. T는 토큰 개수. "T줄 × d_model칸 표"라는 뜻입니다.

💡 **비유**: 게임 캐릭터의 "능력치 카드"입니다. 힘 0.3, 민첩 -1.2, 지능 0.8…. 처음엔 아무렇게나 적혀 있지만, 게임(학습)을 하면서 점점 그 캐릭터에 맞는 능력치로 고쳐집니다.



## 슬라이드 9. 임베딩 공간 — 비슷한 의미는 가까이

* 학습이 끝나면 의미가 비슷한 단어의 벡터는 서로 **가까이** 모입니다. 강아지·고양이·호랑이는 동물끼리, 사과·바나나·포도는 과일끼리 모이고, 자동차는 혼자 멀리 있습니다.
* 실제 벡터는 수백~수만 칸이라 눈으로 볼 수 없어서, 그림은 2차원(종이 위의 점)으로 단순화한 것입니다.
* **거리 = 의미의 차이**: 가까울수록 비슷한 뜻.
* 유명한 예: **왕 − 남자 + 여자 ≈ 여왕**. 벡터로 더하기·빼기를 했더니 의미 관계가 계산되었습니다.

💡 **비유**: 학교 운동장에서 취미가 비슷한 친구끼리 모여 서 있는 모습입니다. 축구부는 한쪽에, 독서부는 다른 쪽에 모이죠. 컴퓨터는 이 "서 있는 위치"를 숫자 좌표로 알고 있는 셈입니다.



## 슬라이드 10. [코드 Step 1] 토큰화와 임베딩 (NumPy)

파일: `numpy_version/step1_embedding.py`. 한 줄씩 읽어 봅시다.

| 코드 | 쉬운 해석 |
| --- | --- |
| `text = "hello transformer"` | 연습용 글 |
| `chars = sorted(set(text))` | 글자를 모으고(`set`: 중복 제거) 정렬(`sorted`) |
| `vocab_size = len(chars)` | 글자 종류가 몇 개인지 센다 → V |
| `stoi = {ch: i ...}` | 글자→번호 사전 |
| `itos = {i: ch ...}` | 번호→글자 사전 (stoi를 뒤집은 것) |
| `encode(s)` | 글 → 번호 목록 |
| `decode(ids)` | 번호 목록 → 글 |
| `d_model = 8` | 벡터 길이를 8로 정함 |
| `rng = np.random.default_rng(0)` | 난수 만드는 기계. **0은 씨앗(seed)**: 고정하면 누가 실행해도 같은 숫자가 나와 결과가 재현된다 |
| `E = rng.normal(0, 1, (vocab_size, d_model))` | 임베딩 표. 평균 0, 퍼짐 1인 랜덤 숫자로 V×8 크기 |
| `ids = np.array(encode("hello"))` | "hello"를 번호 배열로 |
| `x = E[ids]` | 번호를 행 번호로 써서 표에서 벡터를 한꺼번에 꺼냄 |

* 결과 `x.shape = (5, 8)`: "hello"는 5글자, 각 글자가 8칸 벡터 → **5줄 × 8칸 표**.
* ⚠️ `sorted`가 중요한 이유: 정렬하지 않으면 실행할 때마다 번호가 달라질 수 있습니다. 정렬해 두면 항상 같은 번호가 나와요.
* 이 `x`가 다음 단계(위치 인코딩, 어텐션)의 **입력**이 됩니다.



## 슬라이드 11. 왜 트랜스포머인가? — RNN의 한계

* **RNN**(과거 방식): 문장을 **한 단어씩 순서대로** 읽습니다. "나는" → "AI를" → "배운다".
  * 앞 단어를 끝내야 다음 단어를 할 수 있어 **병렬(동시에 처리)이 어렵고 느립니다.**
  * 문장이 길면 앞부분을 점점 **잊어버립니다.**
  * 멀리 떨어진 단어끼리의 관계를 잡기 어렵습니다.
* **트랜스포머**: **모든 단어가 모든 단어를 직접** 바라봅니다(어텐션). 한꺼번에 계산하니 GPU(계산 전용 장치)에서 아주 빠르고, 거리와 상관없이 관계를 바로 연결합니다.

💡 **비유**: RNN은 **귓속말 전달 게임**입니다. 처음 말이 끝에 가면 변해 있죠. 트랜스포머는 **원탁 회의**입니다. 모두가 한자리에 앉아 서로 직접 이야기합니다.

## 슬라이드 13. 트랜스포머 전체 구조 한눈에 (오늘의 지도)

**아래에서 위로** 한 방향으로 읽습니다.

1. 입력 문장
2. 토큰화 (글자 → 번호)
3. 임베딩 + 위치 인코딩 (번호 → 벡터, 순서 정보 추가)
4. **트랜스포머 블록 × N** (어텐션 + FFN을 N번 반복)
5. LayerNorm (값 가지런히)
6. Linear: 어휘 크기 V개의 점수를 만듦
7. softmax → **다음 토큰 확률**

* 블록 안에서는 딱 두 줄이 일어납니다.
  * `x = x + 어텐션(LayerNorm(x))`
  * `x = x + FFN(LayerNorm(x))`
* 층을 하나씩 통과할 때마다 단어 벡터가 문맥을 담아 **점점 똑똑해집니다.**
* 마지막 위치의 출력 점수 → softmax → "다음에 올 토큰"의 확률 분포.

💡 **비유**: 공장 컨베이어 벨트. 재료(글자)가 들어와 번호표(토큰) → 능력치(임베딩) → 여러 작업대(블록)를 거쳐 마지막에 "다음 글자는 이거일 확률 40%"라는 상품이 나옵니다. 매 교시 시작할 때 이 지도를 다시 보며 "지금 어디쯤인지" 확인할 거예요.

## 슬라이드 16. 문제: 어텐션은 단어의 순서를 모른다

* "개가 사람을 물었다" vs "사람이 개를 물었다". 단어는 같지만 **뜻이 완전히 다릅니다!**
* 어텐션은 단어들을 **집합(주머니)처럼 한꺼번에** 처리해서, 단어가 같으면 순서를 바꿔도 같은 계산이 됩니다. (RNN은 순서대로 읽어서 자동으로 알았죠.)
* **해결**: 각 토큰 벡터에 "나는 몇 번째야"를 알려 주는 **위치 벡터를 더합니다.**
  * 입력 = 단어 임베딩 + 위치 인코딩

💡 **비유**: 카드를 섞어 놓았더니 순서를 알 수 없습니다. 그래서 카드마다 **번호표 스티커**를 붙여 줍니다.



## 슬라이드 17. 위치 인코딩 아이디어: 시계의 바늘

* 시계의 시침·분침·초침은 서로 다른 속도로 돕니다. 세 바늘의 각도를 합치면 하루 중 어느 시각이든 **유일하게** 표현할 수 있습니다.
* 위치 인코딩도 같습니다. 서로 다른 속도로 흔들리는 파형(사인·코사인)을 여러 개 씁니다.
  * 빠르게 도는 파형(차원 0, 1) → 위치의 **세밀한** 차이
  * 중간 속도 파형(차원 2, 3) → **중간** 차이
  * 느리게 도는 파형(차원 4, 5…) → **큰** 차이
* 사인·코사인을 쓰는 이유 3가지
  * 값이 항상 −1~1이라 임베딩을 망가뜨리지 않는다.
  * 학습이 필요 없고, 훈련 때 못 본 **긴 문장에도 계산**할 수 있다.
  * **가까운 위치끼리는 비슷한 벡터**가 된다.

💡 **비유**: 시계가 "3시 14분 15초"를 세 바늘의 모양으로 알려 주듯, 각 위치도 여러 파도의 높낮이 조합으로 자기 번호를 알려 줍니다.



## 슬라이드 18. 위치 인코딩 공식과 모양

* 공식은 그림으로 제공됩니다. 말로 풀면:
  * 짝수 칸: `PE(pos, 2i) = sin( pos / 10000^(2i/d_model) )`
  * 홀수 칸: `PE(pos, 2i+1) = cos( pos / 10000^(2i/d_model) )`
  * `pos` = 몇 번째 단어인지, `i` = 몇 번째 차원 쌍인지.
* 분모 `10000^(2i/d)`가 차원이 뒤로 갈수록 커져서, **왼쪽 차원일수록 빠르게, 오른쪽 차원일수록 느리게** 변합니다.
* 그림: 가로 = 차원, 세로 = 위치. 왼쪽은 줄무늬가 촘촘하고 오른쪽은 넓게 변합니다.



## 슬라이드 19. [코드 Step 2] 위치 인코딩 (NumPy)

| 코드 | 쉬운 해석 |
| --- | --- |
| `pos = np.arange(max_len)[:, None]` | 0,1,2,…를 **세로로** 세움 → 모양 (max_len, 1) |
| `i = np.arange(0, d_model, 2)[None, :]` | 0,2,4,…를 **가로로** 세움 → 모양 (1, d/2) |
| `angle = pos / np.power(10000.0, i / d_model)` | 세로×가로 표가 한 번에 계산됨(브로드캐스팅) |
| `pe[:, 0::2] = np.sin(angle)` | 0,2,4번째 열(짝수)에 sin |
| `pe[:, 1::2] = np.cos(angle)` | 1,3,5번째 열(홀수)에 cos |
| `x_in = x + pe[:x.shape[0]]` | 임베딩에 위치표의 앞부분을 **더함** |
| `pe[0] @ pe[1]` → 15.3 | 위치 0과 1(가까움)의 내적 |
| `pe[0] @ pe[48]` → 5.3 | 위치 0과 48(멈)의 내적. **거리가 멀수록 작아짐** |

* 🔍 **브로드캐스팅**: 세로 한 줄과 가로 한 줄을 만나게 하면 "구구단표"처럼 모든 조합이 한 번에 만들어지는 NumPy의 기능입니다.
* 🔍 **내적**(곱해서 더하기)은 두 벡터가 얼마나 닮았는지 알려 줍니다(슬라이드 23 참고). 가까운 위치일수록 닮았다는 것을 검산한 겁니다.
* `pe`는 **학습하지 않는 상수**입니다. 한 번 만들어 계속 씁니다.



## 슬라이드 20. 셀프 어텐션 직관: 도서관에서 책 찾기

세 가지 역할이 있습니다.

* **Query(질문, Q)**: "AI 입문서 있나요?" — 내가 지금 찾고 싶은 것
* **Key(색인·이름표, K)**: 책등에 적힌 제목·분류 — "나는 이런 정보를 가졌어요"
* **Value(내용, V)**: 책의 실제 내용 — 선택된 책에서 얻는 정보

> 질문(Q)과 이름표(K)가 잘 맞을수록 → 그 책의 내용(V)을 **많이** 가져온다.

* 문장 속 **모든 단어가 각자 Q, K, V를 가집니다.** 그리고 모두가 동시에 "나는 누구를 얼마나 참고할까?"를 계산합니다.

💡 **비유**: 도서관에서 "AI 입문서"라는 질문을 들고 책등을 쭉 훑어봅니다(Q와 K 비교). 맞는 책일수록 더 꼼꼼히 읽고(V를 많이 가져오고), 상관없는 책은 거의 안 읽습니다.



## 슬라이드 21. 예: "그것"은 무엇을 가리킬까?

* 문장: "강아지가 길을 건너지 못했다. **그것은** 너무 피곤했다."
* 사람은 "그것 = 강아지"를 바로 압니다. 어텐션은 "그것"이 다른 단어를 얼마나 참고할지를 **숫자**로 계산합니다.

| 강아지 | 길 | 건너지 | 못했다 | 그것 |
| --- | --- | --- | --- | --- |
| **0.62** | 0.15 | 0.08 | 0.05 | 0.10 |

* 합 = 1.00 (비율이 된다). 가장 큰 가중치(0.62)를 가진 "강아지"의 정보를 많이 섞어서 "그것"의 새로운 벡터를 만듭니다. 그래서 컴퓨터도 "그것 = 강아지"를 이해하게 됩니다.

💡 **비유**: 피자 한 판을 단어들에게 나눠 주는 겁니다. 강아지에게 62%, 길에게 15%… 합치면 꼭 한 판(100%)이에요.



## 슬라이드 22. 1단계: 입력 X에서 Q, K, V 만들기

* 입력 `X`(모양 T × d_model)에 서로 다른 **가중치 행렬** 세 개를 곱합니다.
  * `Q = X · Wq`, `K = X · Wk`, `V = X · Wv`
* `Wq, Wk, Wv`는 **학습으로 바뀌는 파라미터**입니다.
* 같은 X에서 **세 가지 다른 관점**(질문 / 이름표 / 내용)을 만드는 셈입니다.
* 모양: `(T, d_model) × (d_model, d_k) = (T, d_k)`. 가운데 숫자(d_model)가 맞아야 곱할 수 있고, 겉의 숫자만 남습니다.
* **셀프(self) 어텐션**: Q, K, V가 모두 **같은 문장**에서 나와서 붙은 이름.

💡 **비유**: 한 사람이 같은 책을 읽고도 "질문 노트", "목차 카드", "요약 노트" 세 가지를 따로 만드는 것과 같습니다. 만드는 요령(W)은 공부하며 좋아집니다.



## 슬라이드 23. 2단계: 점수 = Q와 K의 내적 (유사도)

* **내적(dot product)**: 같은 자리끼리 곱해서 모두 더하기.
  * `a=[1,2,3]`, `b=[4,5,6]` → 1×4 + 2×5 + 3×6 = **32**
  * 방향이 비슷하면 크고, 반대면 작습니다(음수).
* 모든 단어 쌍을 한 번에: **Q · Kᵀ**
  * `(T, d_k) × (d_k, T) = (T, T)` 크기의 표가 만들어집니다.
  * (i, j)칸 = "i번 단어의 질문이 j번 단어의 이름표와 얼마나 맞나"
* 예시 표(T=3): 대각선(자기 자신)이 크게 나오는 경향이 있습니다. **한 행 = 한 단어의 "참고 점수표".**

(Kᵀ의 T는 "전치", 표의 가로세로를 뒤집는다는 뜻입니다. 같은 문자 T지만 토큰 개수 T와는 다른 의미예요.)



## 슬라이드 24. √d_k로 나누기

* 슬라이드 제목은 그림으로 되어 있습니다. 내용은 **"점수를 √d_k로 나눈다"**는 것입니다.
* 이유: 차원(d_k)이 클수록 내적 값의 크기도 커집니다(성분이 평균 0, 분산 1일 때의 통계적 성질).
  * 값이 너무 크면 softmax가 **한 칸만 1에 가깝게 쏠립니다.**
  * 예: `softmax([20, 1, 0]) ≈ [1, 0, 0]` → 기울기가 거의 0 → **학습이 진행되지 않습니다.**
* 그래서 √d_k로 나눠서 점수의 크기를 알맞게 유지합니다.

💡 **비유**: 시험 점수가 20점, 1점, 0점이면 20점이 압도적이라 나머지는 아예 무시됩니다. 점수를 적당히 줄여서 비교하면 모두가 "조금씩이라도" 의견을 낼 수 있습니다.

## 슬라이드 25. 3단계: softmax로 점수를 확률(비율)로

* 점수는 음수도 되고 합이 제멋대로입니다. softmax는 이를 **0~1 사이의 비율, 합이 1**로 바꿉니다.
* 계산 순서 (점수 `[2.0, 1.0, 0.1]`)
  1. 각각 `exp`(e의 거듭제곱): 7.39, 2.72, 1.11 (모두 양수가 됨)
  2. 전부 더함: 7.39 + 2.72 + 1.11 = 11.22
  3. 각각 나눔: 7.39/11.22 = **0.66**, 0.24, 0.10
* **수치 안정화**: `exp(1000)`은 컴퓨터가 감당 못 하는 큰 수(overflow)입니다. 모든 점수에서 **최댓값을 먼저 빼도** 결과는 같습니다. `softmax(z) = softmax(z − max(z))`
* **행 단위 적용**: 점수표 (T, T)의 각 행에 softmax(`axis=-1`) → 한 단어가 모든 단어에 주는 비율.

💡 **비유**: 득표수로 지분을 나누는 것. 점수가 높을수록 더 큰 조각을 받지만, 누구도 음수가 되진 않고 전체는 항상 100%입니다.



## 슬라이드 26. 4단계: 비율대로 V를 섞는다 (손으로 계산)

설정: `X = Q = K = V = [[1,0],[0,1],[1,1]]` (토큰 3개, d_k=2)

① **점수** `Q·Kᵀ/√2`: 먼저 Q·Kᵀ는 `[[1,0,1],[0,1,1],[1,1,2]]`. 이것을 √2≈1.414로 나눠 `[[0.71,0,0.71],[0,0.71,0.71],[0.71,0.71,1.41]]`.

② **softmax** (행마다): 첫 행 `[0.71, 0, 0.71]` → `[0.40, 0.20, 0.40]`. 같은 방식으로 `[0.20,0.40,0.40]`, `[0.25,0.25,0.50]`.

③ **출력 = 가중치 · V**: 첫 번째 토큰
* 출력₀ = 0.40×[1,0] + 0.20×[0,1] + 0.40×[1,1]
* = [0.40, 0] + [0, 0.20] + [0.40, 0.40] = **[0.80, 0.60]**
* 첫 단어는 자기 자신과 세 번째 단어를 **40%씩**, 두 번째를 **20%** 섞은 새로운 벡터가 됐습니다.

💡 **비유**: 물감 섞기. 빨간색 40, 파란색 20, 보라색 40을 섞었더니 새 색(0.80, 0.60)이 나왔습니다.



## 슬라이드 27. 어텐션 공식 총정리와 shape 추적

> **Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V**

모양 추적 (매우 중요한 습관):

| 단계 | 모양 |
| --- | --- |
| 입력 X | (T, d_model) |
| Q, K, V | (T, d_k) |
| Q·Kᵀ/√d_k | (T, T) |
| softmax | (T, T) |
| ·V | (T, d_k) |

* 입력과 출력의 **줄 수(T)는 그대로**입니다. 단어 수는 같고, 각 벡터가 "문맥을 반영한 새 벡터"로 바뀝니다.
* 🔧 **디버깅 팁**: 단계마다 `print(x.shape)`를 하면 대부분의 버그가 바로 보입니다.



## 슬라이드 28. [코드 Step 3] 어텐션 함수 (NumPy)

**softmax 함수**
* `x = x - x.max(axis=axis, keepdims=True)`: 최댓값을 빼서 overflow 방지
* `e = np.exp(x)`: 지수 취하기
* `return e / e.sum(...)`: 합으로 나누어 비율로

**scaled_dot_product_attention**
* `d_k = Q.shape[-1]`: 마지막 모양 숫자(벡터 길이)
* `scores = Q @ K.T / np.sqrt(d_k)`: 모든 단어 쌍 점수를 **행렬곱 한 번**에 (`@`는 행렬곱 기호)
* `if mask is not None: scores = np.where(mask, -1e9, scores)`: 마스크가 True인 칸을 아주 작은 수(−10억)로 덮음 → 못 보는 칸
* `weights = softmax(scores, axis=-1)`: 각 행의 합 = 1
* `return weights @ V, weights`: 비율대로 V를 섞은 결과와 비율표를 돌려줌

사용: `Q, K, V = x @ Wq, x @ Wk, x @ Wv` 후 함수 호출.



## 슬라이드 29. 인과 마스크(Causal Mask): 미래는 볼 수 없다

* GPT는 **다음 단어를 맞혀야** 합니다. 정답이 될 미래 단어를 미리 보면 **시험지를 훔쳐보는 것**이죠!
* 표(1=허용, 0=차단)는 **아래쪽 삼각형만 1**입니다. i번째 단어는 자기 자신과 **앞 단어(≤ i)만** 참고합니다.

```
1 0 0 0
1 1 0 0
1 1 1 0
1 1 1 1
```

* 구현 방법
  1. 대각선 위쪽이 True인 마스크 만들기: `np.triu(np.ones((T,T), bool), k=1)`
  2. softmax 전에 True 칸을 −1e9로 덮어쓰기
  3. `softmax(−1e9) ≈ 0` → 가중치 0
* 번역의 **인코더**처럼 문장 전체를 봐도 되는 경우에는 마스크를 쓰지 않습니다.

💡 **비유**: 책 읽으며 다음 장을 손으로 가리고 줄거리를 맞히는 놀이. 앞부분만 보고 다음을 추측하는 연습을 하는 겁니다.



## 슬라이드 30. 실제 어텐션 가중치: 마스크 전과 후

* 히트맵(색 표) 읽는 법: **행 = 질문하는 단어(Q), 열 = 참고되는 단어(K), 진할수록 많이 참고.**
* 왼쪽(마스크 전)은 모든 칸에 값이 있고, 오른쪽(마스크 후)은 위쪽 삼각형이 0이 되어 **"과거만"** 봅니다.
* 코드: `out, w = scaled_dot_product_attention(Q, K, V, mask=causal_mask(T))`
* `assert np.allclose(np.triu(w, k=1), 0)`: "대각선 위쪽이 전부 0이다"를 컴퓨터가 **자동 검산**합니다. 틀리면 에러가 나서 바로 알 수 있어요.



## 슬라이드 31. 2교시 정리 퀴즈

* ✍️ **Q1. 위치 인코딩을 임베딩에 "더하는" 이유?** → 어텐션은 순서를 모르므로, 단어에 "몇 번째인지" 정보를 섞어 주기 위해서.
* ✍️ **Q2. Q, K, V의 역할?** → Q·K의 유사도로 V를 **섞을 비율**을 정한다. (Q=질문, K=이름표, V=내용)
* ✍️ **Q3. 인과 마스크가 없으면?** → 학습 때 미래의 정답을 훔쳐보게 되어, 진짜 예측 연습이 되지 않는다.

# 1회차 · 3교시 — 멀티헤드와 트랜스포머 블록

## 슬라이드 32. 3교시 시작

* 어텐션을 확장(멀티헤드)하고, 나머지 부품(FFN·잔차·LayerNorm)을 붙여 **블록**을 완성합니다.



## 슬라이드 33. 멀티헤드 어텐션: 여러 관점으로 동시에 본다

* 한 번의 어텐션은 "한 가지 관계"만 보기 쉽습니다. 그래서 **작은 어텐션(head)을 여러 개 나란히** 돌립니다.
  * Head 1: 문법 관계 (주어 ↔ 동사)
  * Head 2: 가까운 단어 (바로 앞·뒤)
  * Head 3: 의미 관계 (대명사 ↔ 대상)
  * Head 4: 기타 패턴 (학습이 알아서 결정)
* 각 헤드의 역할은 사람이 정해 주지 않아도 **학습이 만듭니다.**
* **비용은 그대로**: d_model=32, 헤드 4개 → 헤드마다 d_k=32/4=**8차원**만 담당. 벡터를 쪼개 쓰므로 계산량은 헤드 1개일 때와 거의 같습니다.

💡 **비유**: 사건을 조사하는 탐정 4명. 한 명은 말투를, 한 명은 알리바이를, 한 명은 CCTV를 봅니다. 마지막에 의견을 모으면 훨씬 정확하죠.



## 슬라이드 34. 멀티헤드 계산 과정: 쪼개고 → 각자 어텐션 → 이어 붙이기

예: d_model=16, 헤드 4개 → d_k=4

1. 입력 x: (T, 16)
2. Q, K, V 만들기: 각 (T, 16)
3. **4개로 쪼개기**: 열 방향으로 [0:4], [4:8], [8:12], [12:16] → 헤드마다 (T, 4)
4. **헤드별 어텐션**: 서로 독립적으로 Step 3의 어텐션 수행
5. **이어 붙이기(concat)**: 결과를 옆으로 붙여 다시 (T, 16)
6. **Wo**: 헤드들의 결과를 섞어 주는 마지막 선형변환 → (T, 16)

* 입력과 출력 shape이 같아서 **층을 쌓을 수 있습니다.**



## 슬라이드 35. [코드 Step 4] 멀티헤드 어텐션 (NumPy)

| 코드 | 쉬운 해석 |
| --- | --- |
| `d_k = d_model // n_heads` | 헤드 하나의 길이. `//`는 나눈 몫. 나누어떨어져야 함 |
| `Q, K, V = x @ Wq, x @ Wk, x @ Wv` | 모든 헤드 몫을 큰 행렬 하나에 모아 둠 |
| `mask = causal_mask(T) if causal else None` | 미래 가리기 |
| `for h in range(n_heads):` | 헤드를 하나씩 돌면서 |
| `s = slice(h*d_k, (h+1)*d_k)` | h번째 헤드가 담당할 열 범위 |
| `scaled_dot_product_attention(Q[:, s], K[:, s], V[:, s], mask)` | Step 3 함수를 **그대로 재사용** |
| `np.concatenate(heads, axis=-1)` | 헤드 결과를 옆으로 이어 붙임 |
| `concat @ Wo` | 헤드 섞기 |

* 검산 아이디어: `n_heads=1`이면 Step 3 결과에 `@ Wo`한 것과 정확히 같아야 합니다.



## 슬라이드 36. 피드포워드 네트워크(FFN): 각 단어가 혼자 생각하는 시간

* **어텐션 = 단어끼리 "회의"하며 정보 교환 / FFN = 각자 자리로 돌아가 "개인 정리"**
* 구조: `Linear(d → 4d) → 비선형 함수(ReLU/GELU) → Linear(4d → d)`
  * 폭을 **4배로 넓혔다가** 다시 원래대로 좁힙니다.
* 모든 위치(토큰)에 **똑같은 가중치를 따로따로** 적용합니다.
* **비선형 함수가 필요한 이유**: 없다면 층을 아무리 쌓아도 결국 하나의 곱셈과 같아집니다. 비선형(구부러짐)이 있어야 복잡한 패턴을 배웁니다.
  * ReLU: 음수는 0으로, 양수는 그대로. 단순하지만 효과 좋음.
* 트랜스포머 파라미터의 **절반 이상**이 FFN에 있습니다.
* 코드: `self.l2(self.l1(x).relu())` → "l1 통과 → relu → l2 통과".

💡 **비유**: 회의(어텐션)를 마친 뒤, 각자 책상으로 돌아가 들은 내용을 곰곰이 정리(FFN)하는 시간입니다.

## 슬라이드 37. 잔차연결(Residual): 지름길을 만들어 준다

* 구조: 입력 x가 층 f를 통과하는 동안 **원본 x도 지름길로 따로 흘러**, 마지막에 `x + f(x)`로 더해집니다.
* **왜 필요?** 층이 아주 깊어지면 학습 신호(기울기)가 중간에서 사라집니다. 지름길 덕분에 기울기가 **곧장 아래층까지** 전달됩니다.
* **의미**: 층은 원본을 통째로 바꿀 필요 없이, **"원본에 보탤 수정분 f만"** 학습하면 됩니다.

💡 **비유**: 숙제 검사를 받을 때 처음부터 다시 쓰는 대신, 선생님이 빨간 펜으로 **고칠 부분만 덧붙이는** 것과 같습니다. 원본은 그대로 살아 있어요. 또 건물의 엘리베이터(지름길)가 있으면 계단을 오르내리느라 힘이 빠지지 않습니다.



## 슬라이드 38. LayerNorm: 벡터의 크기를 가지런히

* 공식: `y = γ · (x − 평균) / √(분산 + ε) + β` (토큰 벡터 하나마다 계산)
  * γ(감마), β(베타)는 학습되는 값(처음엔 1과 0). ε(엡실론)은 0으로 나누기를 막는 아주 작은 수.
* **손계산**: x = [2, 4, 6, 8]
  1. 평균 = (2+4+6+8)/4 = **5**
  2. 평균을 뺌: [−3, −1, 1, 3]
  3. 분산 = (9+1+1+9)/4 = **5**, 표준편차 = √5 ≈ 2.24
  4. 표준편차로 나눔: **[−1.34, −0.45, 0.45, 1.34]** → 평균 0, 퍼짐 1이 됨
* **왜 필요?** 층을 지나며 값이 너무 커지거나 작아지면 학습이 불안정해집니다. 평균 0, 분산 1로 맞추면 안정적이고 빨리 학습됩니다.
* **BatchNorm과의 차이**: LayerNorm은 "한 토큰 벡터 **안**"(마지막 축)에서 계산하므로 문장 길이·배치 크기에 영향받지 않아 언어모델에 적합합니다.

💡 **비유**: 키가 제각각인 아이들을 "평균 키를 기준으로 얼마나 크고 작은가"로 줄 세우는 일. 단위가 정리되어 비교가 쉬워집니다.



## 슬라이드 39. 트랜스포머 블록 조립

위에서 아래로(데이터가 흐르는 순서):

1. 입력 x
2. LayerNorm → 멀티헤드 어텐션(마스크) → `+ 잔차` (원본 x를 더함)
3. LayerNorm → FFN → `+ 잔차`
4. 출력 x' (**shape 동일**)

딱 두 줄이면 끝!
```
x = x + attn( ln1(x) )
x = x + ffn( ln2(x) )
```

* **역할 분담**: 어텐션=단어↔단어 정보 교환 / FFN=단어 하나를 깊게 가공 / 잔차·정규화=깊게 쌓아도 학습이 잘 되게.
* **블록은 레고**: 입력·출력 모양이 같으므로 N개를 그대로 쌓을 수 있습니다. (GPT-3는 96개!)
* 🔍 참고(발표자 노트): 이 방식은 Pre-LN(LayerNorm을 먼저)입니다. 원 논문은 Post-LN이지만 현대 모델은 대부분 Pre-LN을 씁니다.



## 슬라이드 40. 블록을 쌓고, 마지막에 "다음 토큰"을 예측

* 흐름: 임베딩(+위치) → 블록 1 → 블록 2 → … → 블록 N → LayerNorm + Linear → softmax
* **shape 흐름**: `(B, T) → (B, T, d) → … → (B, T, d) → (B, T, V)`
  * B = 한 번에 처리하는 문장 개수(배치), T = 글자 수, d = 벡터 길이, V = 어휘 크기
* **출력층의 의미**: 각 위치마다 어휘 V개의 점수(logits)를 냅니다. softmax를 하면 "다음 토큰이 각 글자일 확률".
  * 예: `"the "` 다음 → 'm' 0.4, 's' 0.3, 'w' 0.1, …
* **한 번에 T개를 학습**: T글자 문장이면 "다음 글자 맞히기" 문제가 T개 한꺼번에 생깁니다. (마스크 덕분에 각 위치는 앞부분만 봅니다.)

## 슬라이드 44. 학습 목표: "다음 글자 맞히기"

* **정답은 문장 안에 이미 있습니다!** 입력을 **한 칸 밀면** 곧바로 정답지가 됩니다. 이를 **자기지도학습**이라 합니다. (사람이 일일이 정답을 달아 줄 필요가 없음)
* 예: 입력 x = a·t·t·e·n·t / 정답 y = t·t·e·n·t·i (한 칸 뒤)
  * "a" 다음은 "t", "at" 다음은 "t", "att" 다음은 "e"… **한 문장 = 여러 문제**. 6문제를 한 번에.
* 코드
  * `x = data[s : s+CTX]`: 입력 구간(s번째부터 CTX글자)
  * `y = data[s+1 : s+CTX+1]`: 한 칸 뒤 = 정답

💡 **비유**: 책을 한 장 밀려 쓴 답안지를 가지고 노는 빈칸 맞히기 놀이. 문제와 정답이 같은 책에서 나옵니다.



## 슬라이드 45. 손실 함수: 틀린 정도를 숫자 하나로

* **교차 엔트로피**: `loss = −log(정답 글자에 준 확률)`. 여러 위치의 평균이 최종 loss입니다.

| 정답에 준 확률 | loss | 의미 |
| --- | --- | --- |
| 0.90 | 0.105 | 거의 맞힘 |
| 0.50 | 0.693 | 반반 |
| 0.10 | 2.303 | 많이 틀림 |
| 0.01 | 4.605 | 완전 틀림 |

* 정답에 높은 확률을 줄수록 loss가 작고, 낮은 확률을 줄수록 급격히 커집니다.
* **학습 전 loss는?** 아무것도 모르면 V개를 똑같이 찍습니다. 확률 = 1/28이므로 `loss = ln(28) ≈ 3.33`. 실험의 첫 loss도 3.5 근처에서 출발합니다.
* **목표**: loss를 0에 가깝게 만들도록 모든 가중치를 조금씩 조정. 그러려면 "어느 가중치를 어느 방향으로 얼마나" 바꿀지 알아야 합니다 → **기울기**.

💡 **비유**: 시험 채점 점수입니다(낮을수록 좋음). 정답에 "90% 확신"했으면 거의 만점, "1% 확신"이었다면 큰 감점.



## 슬라이드 46. 경사하강법: 안개 낀 산을 내려오기

* 안개 낀 산에서 길을 잃었습니다. 발밑의 **기울기**(어느 쪽이 가장 가파른 오르막인가)만 알 수 있어요. **그 반대로 한 걸음씩** 내려가면 결국 낮은 곳(loss가 작은 곳)에 도착합니다.
* **한 줄 규칙**
  * 기울기 = 내 위치에서 "가장 가파르게 올라가는 방향". 그 반대로 가면 loss가 줄어든다.
  * **lr(학습률)** = 한 걸음 크기. 너무 크면 튕겨 나가고, 너무 작으면 느립니다.
  * **Adam**: 과거 기울기의 평균으로 방향과 보폭을 부드럽게 조절하는 똑똑한 버전.

💡 **비유**: 눈을 가리고 언덕을 내려갈 때, 발바닥 느낌으로 "이쪽이 내리막이네" 하며 조금씩 걷는 것과 같습니다.



## 슬라이드 47. 역전파와 연쇄법칙: 결과에서 거꾸로 기울기 전달

* 예: `L = (a·b + a).sum()`, a=[1,2,3], b=[4,5,6]
  * 계산 순서: `u = a·b` → `v = u + a` → `L = Σv`
* **연쇄법칙**: 결과에서 거꾸로 올라가며 각 단계의 변화율을 곱해 갑니다.
  * `∂L/∂a = (∂L/∂v)(∂v/∂u)(∂u/∂a) + (∂L/∂v)(∂v/∂a) = 1·b + 1 = b+1 = [5,6,7]`
  * (a는 두 군데서 쓰였으니 두 경로를 **더합니다**.)
  * 기호 `∂L/∂a`는 "a를 살짝 바꾸면 L이 얼마나 변하나"라고 읽습니다.
* **핵심 아이디어**: 각 연산은 **자기 국소 미분**(자기 바로 앞뒤만의 변화율)만 알면 됩니다. 나머지는 뒤에서 오는 기울기에 곱해서 넘기면 됩니다.

💡 **비유**: 도미노가 쓰러진 걸 보고 "맨 처음 누가 잘못 밀었을까?"를 뒤에서 앞으로 거슬러 가며 책임을 나눠 주는 일. 도미노마다 "나는 앞 도미노의 영향을 이만큼 받았어"만 알면 됩니다.



## 슬라이드 48. 자동미분 엔진 설계: Tensor가 기억하는 3가지

① **data / grad**: data는 실제 값(NumPy 배열), grad는 ∂L/∂(이 값). 처음엔 0이고 backward 때 채워집니다.
② **parents**: 이 값을 **만든 입력들**. 계산 그래프를 거슬러 올라가는 "길".
③ **_backward()**: "내 기울기를 입력들에게 나눠 주는 방법"이 담긴 함수. 연산마다 다릅니다.

* **backward()가 하는 일**
  1. 그래프를 **위상 정렬**(입력이 먼저 오도록 줄 세우기)
  2. `loss.grad = 1`로 시작 (L을 L로 미분하면 1)
  3. 결과 → 입력 순서로 각 노드의 `_backward()` 실행
  * ※ 같은 값이 여러 곳에 쓰이면 기울기를 **더합니다(+=)**.

💡 **비유**: 요리의 "레시피 기록". 완성 요리가 맛없으면(loss) 그 요리를 만든 재료와 순서(parents)를 거꾸로 따라가며 "이 재료를 얼마나 줄일까"를 알려 주는 것입니다.



## 슬라이드 49. [코드 Step 5-1] Tensor 클래스: 덧셈과 곱셈

| 코드 | 쉬운 해석 |
| --- | --- |
| `self.data = np.asarray(data, dtype=np.float64)` | 값 저장(소수 형태) |
| `self.grad = np.zeros_like(self.data)` | 기울기 칸을 0으로 준비 |
| `self.parents = parents` | 나를 만든 입력 기억 |
| `self._backward = lambda: None` | 아직 할 일 없음(처음 입력 값은 역전파 방법이 없음) |
| `out = Tensor(self.data * other.data, (self, other))` | 곱셈 결과를 만들되 부모를 기록 |
| `self.grad += unbroadcast(out.grad * other.data, ...)` | a의 기울기 = (나온 기울기) × b |
| `other.grad += unbroadcast(out.grad * self.data, ...)` | b의 기울기 = (나온 기울기) × a |
| `out._backward = _backward` | 결과에 역전파 방법을 붙여 둠 |

* **클로저**: `_backward`는 만들어질 때의 `self`, `other`, `out`을 기억하는 함수입니다.
* **곱셈의 국소 미분**: a×b에서 a를 조금 바꾸면 결과는 b배로 변하니까, a의 기울기는 b에 비례합니다.
* **`+=`**: 한 값이 여러 번 쓰이면 기울기가 합쳐져야 해서.
* **unbroadcast**: 작은 배열이 큰 모양으로 "복사되어 계산"된 경우, 역전파 때 큰 기울기를 원래 모양으로 합쳐 줍니다.



## 슬라이드 50. [코드 Step 5-2] 행렬곱, softmax 그리고 backward()

* **행렬곱** `C = A @ B`의 역전파: `dA = dC · Bᵀ`, `dB = Aᵀ · dC` (swap = 마지막 두 축 교환).
* **softmax 역전파**: 공식 한 줄 `dx = s*(dy − sum(dy*s))`로 충분합니다. (s = softmax 결과)
* **backward()**
  * `order = [...]`: 위상 정렬(입력이 먼저)
  * `self.grad = np.ones_like(self.data)`: dL/dL = 1
  * `for t in reversed(order): t._backward()`: 결과 → 입력 순서로 실행
* 그 외 add, mul, pow, sum, reshape, transpose, relu, masked_fill, take(임베딩), cross_entropy도 같은 방식으로 구현합니다.
* 전체 파일은 약 200줄! **PyTorch autograd의 축소판**입니다.



## 슬라이드 51. 기울기 검사(Gradient Check): 내가 만든 미분이 맞나?

* **수치 미분**: `f'(w) ≈ [f(w+h) − f(w−h)] / 2h`. h를 아주 작게(1e-6) 잡고 값을 **살짝 흔들어서** 실제로 loss가 얼마나 변하는지 측정합니다.
* 코드 흐름
  1. `loss.backward()`로 내가 만든 기울기 구하기
  2. 가중치의 칸을 하나씩 `+h`, `-h` 했을 때의 loss를 재서 `(lp - lm)/(2*h)` 계산 → 수치 기울기
  3. `assert np.allclose(num, W.grad, atol=1e-6)`: 두 값이 거의 같은지 확인
* 결과: 최대 오차 ≈ 1.4e-10 (0.00000000014). **통과!** 오차가 1e-6보다 작으면 올바른 구현.
* **실무 팁**: 새 연산을 만들 때마다 기울기 검사를 하는 습관을! (느려서 학습엔 쓰지 않음)

💡 **비유**: 공식으로 구한 답을 "실제로 해 봐서" 맞는지 확인하는 검산입니다.

## 슬라이드 53. 조립 설계도: 클래스 하나 = 부품 하나

* 부품 6개: `Linear`(y=xW+b), `LayerNorm`(γ, β), `MultiHeadAttention`(q,k,v,o 4개의 Linear), `FeedForward`(Linear 2개+ReLU), `Block`(ln1·attn·ln2·ffn), `GPT`(emb + Block×N + head), 그리고 `Adam`(가중치 갱신).

💡 **비유**: 레고 블록마다 같은 모양의 "연결 돌기"가 있어서 어떤 것끼리도 끼워 맞출 수 있는 것과 같습니다.



## 슬라이드 54. [코드 Step 6-1] Linear와 LayerNorm

**Linear**
* `self.W = Tensor(rng.normal(0, 1/np.sqrt(n_in), size=(n_in, n_out)))`: 가중치 행렬. 초기값은 입력이 많을수록 작게 → 출력이 폭주하지 않음.
* `self.b = Tensor(np.zeros(n_out))`: 편향(b), 처음엔 0.
* `y = x @ self.W` 후 `y + self.b`.

**LayerNorm**
* `gamma=1, beta=0`으로 시작.
* `mu = x.mean(...)`: 평균, `xc = x − mu`: 평균 뺌, `var = (xc*xc).mean(...)`: 분산.
* `xc * ((var + eps) ** -0.5) * gamma + beta`: 표준편차로 나누고 γ·β 적용. (`** -0.5`는 1/√)

* **핵심**: LayerNorm은 **새 연산을 만들지 않고** mean, −, ×, ** 만 조합했습니다. 조합만 해도 자동미분이 알아서 기울기를 구해 줍니다!



## 슬라이드 55. [코드 Step 6-2] 멀티헤드 어텐션 (배치 + 자동미분)

* Step 4의 `for` 문 대신 헤드를 **새 축**으로 만들어 한 번에 계산합니다.
* `split(t)`: `(B,T,D) → reshape → (B,T,h,dk) → transpose(0,2,1,3) → (B,h,T,dk)`. 즉 헤드를 앞쪽 축으로 옮깁니다.
* `scores = (q @ k.transpose(0,1,3,2)) * (1/√dk)`: `(B,h,T,T)`. **모든 문장·모든 헤드**의 점수를 한 번에.
* `mask = np.triu(np.ones((T,T), dtype=bool), k=1)`: 미래 가리기.
* `w = scores.masked_fill(mask, -1e9).softmax()`: Step 3과 같은 순서.
* `ctx = (w @ v).transpose(0,2,1,3).reshape(B,T,D)`: 다시 모양을 되돌려 헤드를 이어 붙임.
* `return self.o(ctx)`: 마지막 선형변환으로 섞음.



## 슬라이드 56. [코드 Step 6-3] FeedForward와 Block

* **FFN**: `l1`은 d→4d(넓힘), `.relu()`, `l2`는 4d→d(좁힘).
* **Block**: 슬라이드 39의 두 줄이 **그대로 코드가 됐습니다.**
  * `x = x + self.attn(self.ln1(x))` ← 잔차연결
  * `x = x + self.ffn(self.ln2(x))`
* `x + ...`의 덧셈이 잔차연결이며, 기울기가 지름길로도 흐릅니다.
* 입력·출력 shape이 같아서 **리스트에 담아 반복 호출**할 수 있습니다.



## 슬라이드 57. [코드 Step 6-4] GPT 모델 전체

* 만드는 부품들 (`__init__`)
  * `emb`: 임베딩 표 (V × d_model, 학습함)
  * `pe`: 위치 인코딩 (상수, 학습 안 함)
  * `blocks`: 블록을 `n_layers`개 만들어 리스트에 담음
  * `ln_f`: 마지막 LayerNorm, `head`: 점수를 내는 마지막 Linear
  * `scale = √d_model`
* 계산 순서 (`__call__`)
  1. `x = self.emb.take(idx) * self.scale + self.pe[:T]`: 번호로 임베딩 조회 → √d를 곱함 → 위치 더함
  2. 블록을 차례로 통과
  3. `return self.head(self.ln_f(x))`: `(B, T, V)` 모양의 다음 글자 점수
* `take`: 번호로 표에서 벡터를 꺼냄(기울기는 해당 행에만 전달).
* **√d_model을 곱하는 이유**: 임베딩 값이 위치 인코딩(−1~1)에 묻히지 않게 키우기 위해서.



## 슬라이드 58. [코드 Step 6-5] Adam 옵티마이저와 학습 루프

**Adam**
* `m`: 과거 기울기의 평균(방향), `v`: 기울기 제곱의 평균(크기).
* `mh`, `vh`: 초반에는 m, v가 0에서 시작해 작게 나오므로 **보정**.
* `p.data -= lr * mh / (sqrt(vh) + eps)`: 파라미터마다 보폭을 조절해 이동.

**학습 루프의 5단계 리듬**
1. `logits = model(x)` — **순전파** (문제 풀기)
2. `loss = ...cross_entropy(y)` — **손실** (채점)
3. `opt.zero_grad()` — **기울기 비우기** (칠판 지우기)
4. `loss.backward()` — **역전파** (틀린 이유 찾기)
5. `opt.step()` — **갱신** (다이얼 조금 돌리기)

* ⚠️ `zero_grad`를 빼먹으면 기울기가 계속 쌓여 학습이 엉망이 됩니다(자주 하는 실수!).
* 이 5단계는 PyTorch에서도 똑같습니다.

💡 **비유**: 시험문제 풀기 → 채점 → 공책 지우기 → 오답노트로 이유 찾기 → 공부법 수정. 이것을 수백 번 반복하면 점수가 오릅니다.

# 2회차 · 6교시 — PyTorch로 실전 버전

## 슬라이드 61. 6교시 시작

* 주제: 같은 모델을 현실적인 방식으로. nn.Module · 자동미분 · GPU. NumPy에서 직접 한 일을 PyTorch가 **대신해 주는 부분**을 확인합니다.



## 슬라이드 62. NumPy 버전 vs PyTorch 버전

| 항목 | NumPy (직접) | PyTorch (실전) |
| --- | --- | --- |
| 미분 | Tensor 클래스 + `_backward` 직접 작성 | `loss.backward()` 한 줄 |
| 부품 | Linear, LayerNorm 직접 구현 | `nn.Linear`, `nn.LayerNorm`, `nn.Embedding` |
| 옵티마이저 | Adam 직접 구현 | `torch.optim.AdamW` |
| 속도 | CPU, 작은 모델만 | GPU 가속, 큰 모델 가능 |
| 장점 | 원리를 100% 이해 | 짧고 빠르고 검증됨, 업계 표준 |

* 한 줄 요약: 원리를 이해한 뒤에 도구를 쓰면, PyTorch의 모든 줄이 **"아, 이거 우리가 직접 만든 거!"**로 읽힙니다.

💡 **비유**: 계산기를 쓰기 전에 손으로 곱셈을 배운 사람은, 계산기가 무슨 일을 하는지 알고 씁니다.



## 슬라이드 63. 우리가 만든 것 ↔ PyTorch 부품 대응표

| 우리가 만든 것 | PyTorch |
| --- | --- |
| `E[ids]` (임베딩 조회) | `nn.Embedding(V, d)` |
| `positional_encoding()` | `register_buffer("pe", pe)` |
| `x @ W + b` | `nn.Linear(d_in, d_out)` |
| LayerNorm 클래스 | `nn.LayerNorm(d)` |
| `masked_fill(mask, -1e9)` | `masked_fill(mask, float('-inf'))` |
| `Tensor.backward()` | `loss.backward()` |
| Adam 클래스 | `torch.optim.AdamW(model.parameters())` |
| `params()` 목록 | `model.parameters()` (자동 수집) |

* `-inf`(음의 무한대)는 `-1e9`보다 더 확실하게 확률 0을 만드는 표현입니다.



## 슬라이드 64. [PyTorch Step 1] 임베딩 + 위치 인코딩

* `class TokenAndPosition(nn.Module)`: PyTorch 부품은 `nn.Module`을 상속하는 클래스입니다.
* `self.tok = nn.Embedding(vocab_size, d_model)`: 임베딩 표 (NumPy의 `E[ids]` 역할).
* `pos`, `div`, `pe`: 위치 인코딩을 만드는 계산. 수식은 같고, `torch.exp(... * -log(10000)/d)`로 쓴 것은 `10000^(−2i/d)`와 같은 값을 만드는 다른 표현입니다.
* `self.register_buffer("pe", pe)`: **파라미터는 아니지만** 모델과 함께 GPU로 이동하고 저장되는 상수.
* `forward(idx)`: `self.tok(idx) * √d_model` 뒤에 `+ self.pe[:T]`.
* `(T, d)`를 `(B, T, d)`에 더하면 B 방향으로 자동 복사(브로드캐스트)됩니다.
* `nn.Module`을 상속하면 안에서 만든 파라미터를 PyTorch가 **자동으로 모아 줍니다.**



## 슬라이드 65. [PyTorch Step 2~3] 멀티헤드 어텐션

* NumPy 버전과 **줄 단위로 같은 흐름**입니다. 달라진 건 도구뿐!
* `self.q/k/v = nn.Linear(..., bias=False)`, `self.o = nn.Linear(...)`: 만드는 부분. (q,k,v는 편향 없이.)
* `register_buffer("causal", torch.tril(torch.ones(max_len, max_len)))`: **tril**은 아래 삼각형이 1인 행렬(허용 칸).
* `split = lambda t: t.view(B,T,h,dk).transpose(1,2)`: 모양을 `(B, h, T, dk)`로.
* `scores.masked_fill(self.causal[:T,:T] == 0, float("-inf"))`: 0인 칸(미래)을 −inf로 가림.
* `F.softmax(scores, dim=-1)`, `self.drop(...)`: softmax 후 dropout.
* `.transpose(1,2).contiguous().view(B,T,D)`: 헤드 합치기. **contiguous()**는 transpose 후 메모리를 정리해야 view를 쓸 수 있어서 필요합니다.
* **dropout**: 학습 중 일부 연결을 무작위로 꺼서 **과적합**(외우기만 하고 응용을 못 하는 현상)을 막습니다.



## 슬라이드 66. [PyTorch Step 4] 트랜스포머 블록

* `nn.Sequential`: 층을 순서대로 이어 붙이는 상자. (Linear → GELU → Linear → Dropout)
* `GELU`: ReLU와 비슷하지만 곡선이 부드러워 GPT 계열이 즐겨 씁니다.
* `Block.forward`의 두 줄은 NumPy 버전과 **완전히 동일**합니다.
* 실행 결과: 블록 하나의 파라미터 12,608개(d=32). NumPy와 약간 다른 것은 편향(bias) 차이 때문입니다. (q,k,v 세 개의 편향 3×32 = 96개가 없어서 12,704 − 96 = 12,608)



## 슬라이드 67. [PyTorch Step 5-1] GPT 모델과 글 생성

* `self.embed = TokenAndPosition(...)`: Step 1의 부품.
* `self.blocks = nn.ModuleList(Block(...) for _ in range(n_layers))`: **ModuleList**로 블록 목록을 모델의 일부로 등록(파라미터 자동 수집).
* `forward(idx, targets=None)`: 임베딩 → 블록들 → `ln_f` → `head`로 `logits (B,T,V)`.
* `F.cross_entropy(logits.view(-1, V), targets.view(-1))`: softmax와 −log를 한 번에 해 주고 수치적으로도 안전합니다. `view(-1, V)`는 `(B,T,V)`를 `(B·T, V)`로 펴서 **모든 위치의 손실을 평균**.
* `targets`를 주면 학습용(loss 반환), 안 주면 추론용으로 쓸 수 있습니다.



## 슬라이드 68. [PyTorch Step 5-2] 학습 루프

* `device = "cuda" if torch.cuda.is_available() else "cpu"`: GPU가 있으면 GPU, 없으면 CPU.
* `model = GPT(...).to(device)`: 모델을 그 장치로 보냄. 데이터도 같은 곳에 있어야 합니다.
* `opt = torch.optim.AdamW(model.parameters(), lr=3e-3, weight_decay=0.01)`: 옵티마이저 생성(weight decay는 가중치가 너무 커지지 않게 살짝 줄이는 규칙).
* `model.train()`: dropout 켜기.
* 5단계 리듬은 NumPy와 같습니다.
  1. `_, loss = model(x, y)` 순전파+손실
  2. `opt.zero_grad(set_to_none=True)` 기울기 비우기
  3. `loss.backward()` 역전파 (**자동미분 한 줄!**)
  4. `nn.utils.clip_grad_norm_(model.parameters(), 1.0)` **클리핑**: 기울기가 너무 크면 잘라 학습 폭주를 막음
  5. `opt.step()` 갱신
* `model.eval()`: dropout 끄기(시험 볼 때는 모든 연결 사용).



## 슬라이드 69. 글 생성: temperature와 top-k

* `@torch.no_grad()`: 기울기 계산이 필요 없음 → 빠르고 메모리 절약. (학습이 아니라 **사용**할 때)
* `generate` 한 바퀴 (`n_new`번 반복)
  1. `self(idx[:, -self.max_len:])`: 최근 토큰만 모델에 넣음
  2. `logits[:, -1, :] / temperature`: **마지막 위치**의 점수를 temperature로 나눔
  3. `top_k`면 상위 k개 밖의 점수는 −inf로 지움
  4. `F.softmax` → `torch.multinomial(probs, 1)`: 확률대로 하나 **뽑기**
  5. `torch.cat([idx, nxt], dim=1)`: 뽑은 글자를 뒤에 붙임
* 설정의 효과

| 설정 | 효과 |
| --- | --- |
| temperature 낮음(0.3) | 가장 그럴듯한 글자만. 안정적·반복적 |
| temperature 높음(1.5) | 다양하지만 엉뚱한 글자도 나옴 |
| top-k = 5 | 상위 5개 후보 안에서만 뽑음 |

* **자기회귀 생성**: 한 글자 예측 → 입력 뒤에 붙임 → 다시 예측. **ChatGPT가 글을 쓰는 방식과 같습니다.**

💡 **비유**: temperature는 "대담함 다이얼"입니다. 낮으면 안전한 선택만, 높으면 모험을 합니다. top-k는 "후보 명단 줄이기"입니다. 이어 쓰기 놀이에서 앞 사람이 쓴 글에 한 글자씩 붙여 가는 것과 같아요.



## 슬라이드 70. PyTorch 학습 결과와 검증

| 항목 | 우리 | 실제 |

## 슬라이드 72. 전체 요약: 트랜스포머를 한 장으로

1. **토큰화·임베딩**: 글자 → 번호 → 벡터 (T, d)
2. **위치 인코딩**: sin/cos를 더해 순서 정보 추가
3. **셀프 어텐션**: softmax(QKᵀ/√d)·V, 마스크로 미래 차단
4. **멀티헤드**: 여러 관점을 병렬로 보고 합친다
5. **블록**: x + attn(ln(x)), x + ffn(ln(x))
6. **출력·학습**: 다음 토큰 확률 → 교차 엔트로피 → 역전파 → Adam

* 마무리 문장: **NumPy로 원리를, PyTorch로 실전을.** 두 버전 모두 직접 돌려 본 당신은 이제 트랜스포머를 "만들 수 있는" 사람입니다!

## 슬라이드 76. ✍️ 솔루션 1. 손계산 어텐션

1. **점수**: `[Q₀·K₀, Q₀·K₁, Q₀·K₂] / √2`
   * Q₀=[1,0]이므로 K₀=[1,0]→1, K₁=[0,1]→0, K₂=[1,1]→1. 즉 `[1, 0, 1] / 1.414 = [0.707, 0, 0.707]`
2. **softmax**: exp = [2.03, 1.00, 2.03], 합 = 5.06 → 가중치 = **[0.401, 0.198, 0.401]**
3. **출력** = 0.401·[1,0] + 0.198·[0,1] + 0.401·[1,1] = **[0.802, 0.599]**
4. **코드 확인**: `scaled_dot_product_attention(X, X, X)` → `w[0]` = `[0.401 0.198 0.401]`, `out[0]` = `[0.802 0.599]`

* 확인 포인트: 가중치의 합 = 1. 자기 자신과 닮은 토큰(0번, 2번)에 큰 가중치가 갔다.



## 슬라이드 77. ✍️ 솔루션 2. 파라미터 수

```python
d, V, L = 32, 28, 2
attn  = 4 * (d*d + d)                 # q,k,v,o = 4,224
ffn   = (d*4*d + 4*d) + (4*d*d + d)   # = 8,352
ln    = 2 * (2*d)                      # gamma,beta x2 = 128
block = attn + ffn + ln                # = 12,704
total = V*d + L*block + 2*d + (d*V + V)
#       임베딩  블록들   ln_f   출력층(head)
```

* 정답: (1) 블록 1개 **12,704** (2) 전체 **27,292** (3) step6 출력 "파라미터 수: 27292"와 일치.
* 자주 틀리는 부분: **임베딩(896), 출력층(924), 마지막 LayerNorm(64)**을 빼먹기 쉽습니다. NumPy 버전은 어텐션의 q,k,v,o **모두 bias를 가집니다.**



## 슬라이드 78. ✍️ 솔루션 3. top-k 샘플링

```python
def top_k_sample(logits, k, rng, temperature=1.0):
    logits = logits / temperature
    cut = np.sort(logits)[-k]                        # 상위 k번째 점수
    logits = np.where(logits < cut, -np.inf, logits) # 탈락
    p = softmax(logits)                              # 탈락한 칸은 확률 0
    return int(rng.choice(len(p), p=p))
```

* ① `np.sort(...)[-k]`: 오름차순 정렬에서 뒤에서 k번째 = **상위 k번째 점수**
* ② 그보다 작은 점수는 −inf로 덮어 탈락
* ③ `softmax(−inf) = 0` → 탈락자는 절대 뽑히지 않음
* 결과: 1000번 모두 1번(3.0)과 3번(2.5)만 나옴 → `[1, 3]`.
* k=1이면 항상 최고점수만 뽑는 **greedy** 방식이 됩니다.
