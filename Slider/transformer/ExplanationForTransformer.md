# Transformer

## 토큰화(Tokenizer)

### 토큰화에서 말하는 어휘란 무엇인가?

* 어휘(vocabulary, vocab)는 모델이 알고 있는 토큰의 전체 목록이다. 각 토큰에는 고유한 번호(ID)가 하나씩 붙는다.
* 모델은 글자나 단어를 직접 읽지 못하고 숫자만 다르다. 그래서 먼저 "이 모델이 쓸 수 있는 조각은 이것들이다"라는 목록을 정해 두고, 조각마다 번호를 매긴다.
* 예시 (이번 강의의 글자 단위 토큰화)
  * 텍스트가 "hello"이면 중복을 뺀 글자는 e, h, l, o이다.

| 토큰 | e    | h    | l    | o    |
| ---- | ---- | ---- | ---- | ---- |
| ID   | 0    | 1    | 2    | 3    |

* 어휘 크기(`vocab_size`)는 4이다.
* `stoi(string $\rightarrow$ int)`는 글자 번호로, `itos(int $\rightarrow$ string)`는 번호를 글자로 바꾸는 사전이다.
* "hello"는 [1, 0, 2, 2, 3]로 인코딩된다.



#### 어휘가 모델 구조에 미치는 영향

* 임베딩 표의 행 수가 `vocab_size`이다. 

* 마지막 출력층도 `vocab_size`이다. 표는 (`vocab_size`, `d_model`) 크기이다.
* 어휘에 없는 토큰은 모델이 표현할 수 없다. 실제로 모델은 이를 `<unk>` 같은 특수 토큰이나 하위 단어 쪼개기로 처리한다.



#### 토큰화 방식별 허위 크기

* 글자 단위: 수십 ~ 수천 개로 작고 단순하지만, 문장이 길어진다. 이 강의는 이 방식이다.
* 단어 단위: 수십만 개로 커지고, 처음 보는 단어 처리하지 못한다.
* 하위 단어(BPE): 보통 3만 ~ 10만 개이다. GPT 같은 실제 모델이 이 방식을 쓴다.

## one-hot 벡터

one-hot 벡터는 어휘 크기만큼 길이를 가지고, 해당 토큰 자리만 1이고 나머지는 전부 0인 벡터이다.

앞의 hello 예시 (어휘 e = 0, h = 1, l = 2, o = 3, `vocab_size=4`)로 보면 이렇다.

| 토큰 | one-hot 벡터 |
| ---- | ------------ |
| e    | [1, 0, 0, 0] |
| h    | [0, 1, 0, 0] |
| l    | [0, 0, 1, 0] |
| o    | [0, 0, 0, 1] |

"hello"는 위 벡터를 쌓은 (5, 4) 행렬이 된다.

> [!NOTE]
>
> #### "hello"가 (5, 4) 행렬이 되는 이유
>
> 행은 토큰(hello를 표현하기 위해서 실제 사용된 토큰) 하나당 한 줄씩 생기고, 열은 어휘 크기만큼 생긴다.
>
> * "hello"는 글자가 5개(h, el, l, l, o)라서 토큰도 5개이다. 그래서 행이 5개이다.
> * 각 토큰의 one-hot 벡터는 길이가 `vocab_size=4`이다. 그래서 열이 4개이다.
>
> 각 토큰의 벡터를 순서대로 한 줄씩 쌓으면 이렇게 된다.
>
> 각 토튼의 벡터를 순서대로 한 줄씩 쌓으면 이렇게 된다.
>
> 
>
> ​       e  h  l  o $\leftarrow$ 열 = 어휘 (4개)
>
> h $\rightarrow$ [0, 1, 0, 0]
>
> e $\rightarrow$ [1, 0, 0, 0]
>
> l $\rightarrow$  [0, 0, 1, 0]
>
> l $\rightarrow$  [0, 0, 1, 0]
>
> o $\rightarrow$ [0, 0, 0, 1]
>
> 
>
> 모양은 (토큰 수, 어휘 크기) = (5, 4)이다.
>
> 
>
> "l"이 두 번 나오므로 세 번째와 네 번째 행이 같다. 어휘에는 중복을 뺀 4종류만 있지만, 문장에는 글자가 5개 있기 때문에 행 수와 열 수가 달라진다.
>
> 
>
> 임베딩을 거치면 열이 d_model로 바뀌어 (5, d_model)이 된다. 슬라이드 앞부분의 "hello" 임베딩이 (5, 8)이었던 것도 d_model=8이라서 같은 이유이다.
>
> 
>
> 앞에서 어휘를 e=0, h=1, l=2, o=3으로 놓았으므로, 위 표의 열 순서는 그 번호 순서(e, h, l, o)를 따랐다.

## 임베딩과 d_model

임베딩(embedding)은 토큰 번호를 의미를 담을 수 있는 실수 벡터로 바꾸는 과정이고, `d_model`은 그 벡터의 길이이다.



### 임베딩

토큰 ID는 그냥 번호표일 뿐이다. "l = 2, o = 3"이라고 해서 o가 l보다 크거나 가깝다는 뜻은 아니다. 모델이 계산에 쓰려면 의미를 담을 수 있는 숫자 묶음이 필요하다.



그래서 임베딩 표 E를 하나 둔다.

* 크기는 `(vocab_size, d_model)`이고, 행 하나가 토큰 하나에 대응한다.
* 토큰 ID가 곧 행 번호이다. `E[2]`를 꺼내면 "ㅣ"의 벡터이다.
* 처음에는 랜덤 값이고, 학습하면서 값이 조금씩 바뀐다. 그 결과 비슷하게 쓰이는 토큰은 비슷한 벡터를 갖게 된다.



```python
import numpy as np
vocab_size, d_model = 4, 8
E = np.random.randn(vocab_size, d_model) * 0.1	# (4, 8) 표
idx = np.array([1, 0, 2, 2, 3])					# "hello"
x = E[idx]										# (5, 8)
```

앞의 one-hot 설명과 같은 결과이다. `E[ids]`는 one-hot $\times$ E를 빠르게 계산한 것이다.



#### d_model

* 토큰 하나를 표현하는 벡터의 길이다. 모델의 "폭"이라고 생각하면 된다.
* 값이 클 수록 토큰 하나에 더 많은 정보를 담을 수 있지만, 파라미터와 계산량도 늘어난다.
* 트랜스포머 안에서는 모든 층의 입력과 출력이 `(토큰 수, d_model)` 모양으로 유지된다. 잔차 연결이 입력과 출력을 더하기 때문이다.
* 멀티헤드 어텐션에서는 `d_model`을 헤드 수로 나눈다. 그래서 `d_model`은 `n_heads`로 나누어 떨어져야 한다.



이 강의의 값은 다음과 같다.

| 버전                  | d_model | 헤드 수          | 헤드당 크기 |
| --------------------- | ------- | ---------------- | ----------- |
| 슬라이드 예시 (hello) | 8       | -                | -           |
| NumPy GPT             | 32      | 4                | 8           |
| PyTorch GPT           | 64      | (코드 확인 필요) | -           |



##### 모양 흐름

> "hello" $\rightarrow$ ids (5, ) $\rightarrow$ 임베딩 E[ids] $\rightarrow$ (5, d_model) $\rightarrow$ + 위치 인코딩 (5, d_model) $\rightarrow$ 블록들 $\rightarrow$ $\cdots$

토큰 수 5는 문장 길이에 따라 달라지고, `d_model`은 모델을 만들 때 정하는 고정값이다.

PyTorch 버전의 헤드 수는 코드를 열어 보지 않아 표에 비워 두었다.

## 위치 인코딩(positional encoding)

위치 인코딩은 각 토큰에 "몇 번째 자리인지" 정보를 더해 주는 벡터이다.



### 왜 필요한가?

어텐션은 토큰들을 한꺼번에 비교하고, 순서를 따로 보지 않기 땜누이다. 임베딩만 넣으면 "나는 너를 좋아해"와 "너를 나는 좋아해"가 같은 토큰 묶음으로 보인다. 그래서 위치마다 고유한 벡터를 만들어 임베딩에 더한다.

> 최종 입력 - 토큰 임베딩 (n, d_model) + 위치 인코딩 (n, d_model)

두 행렬의 모양이 같아서 단순히 더할 수 있다.

사인/코사인 방식 (이 강의에서 사용하는 방식)

위치 pos와 차원 i에 대해 이렇게 계산한다.

> PE[pos, 2i] = sin(pos / 10000^(2i / d_model))
>
> PE[pos, 2i+1] = cos(pos / 10000^*(2i / d_model))

* 짝수 차원은 sin, 홀수 차원은 cos를 사용한다.
* 차원 번호가 클수록 분모가 커져서 파장이 길어진다. 앞쪽 차원은 빠르게 변하고, 뒤쪽 차원은 천천히 변한다.
* 시계의 초침, 분침, 시침이 함께 시각을 나타내는 것과 비슷하다. 여러 속도의 파동을 조합하면 위치마다 서로 다른 벡터가 나온다.



```python
import numpy as np

def positional_encoding(max_len, d_model):
    pos = np.arange(max_len)[:, None]              # (max_len, 1)
    i = np.arange(0, d_model, 2)[None, :]          # (1, d_model/2)
    angle = pos / (10000 ** (i / d_model))         # (max_len, d_model/2)
    pe = np.zeros((max_len, d_model))
    pe[:, 0::2] = np.sin(angle)
    pe[:, 1::2] = np.cos(angle)
    return pe

x = embedding + positional_encoding(5, 8)          # (5, 8) + (5, 8)
```

#### 특징

* 학습하는 값이 아니다. 공식으로 한 번 계산해서 쓰므로 파라미터가 늘지 않는다.
* 값의 범위기 -1~1이다. 임베딩 값을 압도하지 않는다.
* 처음 보는 긴 길이에도 계산할 수 있다. 공식이라서 `max_len`만 늘리면 된다.
* 위치 0은 고정된 모양이다. sin(0)=0, cos(0)=1이므로 [0, 1, 0, 1, ...]이다.



GPT 계열의 PyTorch 구현에서는 위치마다 학습되는 임베딩 표`(nn.Embedding(max_len, d_model))`를 쓰는 방식도 흔하다. 방식만 다를 뿐 "임베딩에 더한다"는 점은 같다.

## 1교시 정리 퀴즈 정답 (슬라이드 발표자 노트 기준)

#### Q1. 컴퓨터에 글자를 넣기 전에 왜 숫자로 바꿔야 할까요?

- 컴퓨터(모델)는 숫자만 계산할 수 있기 때문입니다. 그래서 글자를 토큰 ID로 바꾸고, 다시 임베딩 벡터로 바꿉니다.



#### Q2. 어휘 크기가 28, d_model이 32라면 임베딩 표의 shape은?

- (28, 32), 즉 (vocab_size, d_model)입니다. 행이 토큰 28종류 하나씩이고, 열은 벡터 길이 32입니다.



#### Q3. RNN 대비 트랜스포머의 장점 두 가지는?

1. 병렬 처리가 가능합니다. RNN은 앞 단어를 처리해야 다음 단어를 처리할 수 있지만, 트랜스포머는 한꺼번에 계산합니다.
2. 먼 단어끼리도 직접 연결됩니다. RNN은 정보가 여러 단계를 거쳐 전달되면서 흐려집니다.

## 어텐션(attention)

어텐션(attention)은 한 토큰이 문장 안의 다른 토큰들을 훑어보고, 관련 있는 토큰의 정보를 더 많이 가져오는 계산이다.



### 직관

"그 동물은 길을 건너지 않았다. 왜냐하면 그것이 너무 피곤했기 때문이다."에서 "그것"의 뜻을 알려면 앞의 "동물"을 봐야 합니다. 어텐션은 "그것"이 모든 단어를 보고, "동물"에 높은 점수를 주고, 그 정보를 많이 섞어 오게 한다.

**Q, K, V**

각 토큰 벡터에서 세 가지를 만든다.

| 이름      | 역할                       | 비유      |
| --------- | -------------------------- | --------- |
| Query (Q) | 내가 찾는 것               | 검색어    |
| Key (K)   | 나는 이런 정보를 갖고 있다 | 문서 제목 |
| Value (V) | 실제로 건네줄 내용         | 문서 본문 |

### 계산 4단계



> $\text{softmax}(Q \cdot K^T / \sqrt{d_k}) V$

1. 유사도 점수: $Q\cdot K^T$로 모든 토큰 쌍의 점수를 구합니다. 모양은 $(n, n)$이다.
2. 크기 조절: $\sqrt{d_k}$로 나눈다. 점수가 너무 커지면 softmax가 한 곳에 쏠려서 학습이 잘 안 되기 때문이다.
3. softmax: 각 행을 합이 1인 비율(가중치)로 바꾼다.
4. 섞기: 그 비율대로 $V$를 가중합한다. 결과는 `(n, d_v)`이다.

```python
import numpy as np

def softmax(x):
    e = np.exp(x - x.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

def attention(Q, K, V, mask=None):
    scores = Q @ K.T / np.sqrt(K.shape[-1])
    if mask is not None:
        scores = np.where(mask, scores, -1e9)   # 못 보게 할 자리는 아주 작은 값
    w = softmax(scores)
    return w @ V, w


```



#### 함께 알아둘 점

- 마스크: GPT는 다음 글자를 맞히는 모델이라, 미래 토큰을 보지 못하게 가린다(인과 마스크).
- 멀티헤드: 어텐션을 여러 개 병렬로 돌려서 서로 다른 관점(문법, 의미 등)을 본다.
- 위치 정보: 어텐션 자체는 순서를 모르므로 위치 인코딩을 따로 더해 준다.

## 멀티헤드 어텐션이란?

멀티헤드 어텐션은 어텐션을 한 번만 하지 않고, 여러 개의 "헤드"로 나눠 동시에 수행한 뒤 결과를 합치는 방식이다.



### 왜 여러 개인가

어텐션 한 번은 "누구를 볼지"를 하나의 점수표로만 정한다. 그런데 한 문장 안에는 여러 관계가 있다. 예를 들어 "그것"은 문법상 주어를, 의미상 "동물"을, 위치상 바로 앞 단어를 동시에 볼 필요가 있다. 헤드마다 서로 다른 `Q/K/V` 변환을 갖게 해서 각자 다른 관계에 집중하게 한다.



### 계산 과정

`d_model=32`, 헤드 4개라면 헤드당 크기는 `d_head = 32 / 4 = 8`이다.

1. `Q, K, V` 만들기: 입력 x (n, 32)에 가중치 `Wq, Wk, Wv`를 곱해 각각 `(n, 32)`를 얻는다.
2. 헤드로 쪼개기: 열 32개를 8개씩 4묶음으로 나눈다. 모양은 `(4, n, 8)`이다.
3. 헤드별 어텐션: 4개 헤드가 각자 $\text{softmax}(QK^T/\sqrt{8})V$를 계산합니다. 결과는 `(4, n, 8)`이다.
4. 이어 붙이기(concat): 다시 $(n, 32)$로 합친다.
5. 출력 변환: 가중치 `Wo`를 곱해 헤드들의 결과를 섞는다. 결과는 `(n, 32)`이다.

입력과 출력의 모양이 `(n, d_model)`로 같아서 블록을 여러 층 쌓을 수 있다.



```python
import numpy as np

def multi_head_attention(x, Wq, Wk, Wv, Wo, n_heads, mask=None):
    n, d_model = x.shape
    d_head = d_model // n_heads
    def split(t):                                    # (n, d_model) -> (heads, n, d_head)
        return t.reshape(n, n_heads, d_head).transpose(1, 0, 2)
    Q, K, V = split(x @ Wq), split(x @ Wk), split(x @ Wv)
    scores = Q @ K.transpose(0, 2, 1) / np.sqrt(d_head)   # (heads, n, n)
    if mask is not None:
        scores = np.where(mask, scores, -1e9)
    e = np.exp(scores - scores.max(-1, keepdims=True))
    w = e / e.sum(-1, keepdims=True)
    out = (w @ V).transpose(1, 0, 2).reshape(n, d_model)  # concat
    return out @ Wo
```



### 알아둘 점

- 파라미터 수는 헤드 수와 무관하다. 헤드를 늘려도 `d_model`을 쪼갤 뿐이라 `Wq, Wk, Wv, Wo` 크기는 `(d_model, d_model)`로 같다.
- `d_model`은 `n_heads`로 나누어떨어져야 한다.
- 헤드가 1개면 보통 어텐션과 같다. 단일 헤드 결과에 `Wo`를 곱한 것과 일치한다.

## 위치 인코딩이 임베딩에 영향을 미치지 않으려면

위치 인코딩은 임베딩에 "더해지는" 값이므로, 값의 크기가 임베딩과 비슷한 범위여야 토큰으 의미가 묻히지 않는다.

값이 크면 왜 문제이가?

`최종 입력 = 임베딩 + 위치 인코딩`이다. 위치 번호를 그대로 쓴다고 가정해 보자.



>위치 0: 임베딩 [0.3, -0.5, ...] + [  0,   0, ... ]
>
>위치 500: 임베딩 [0.3, -0.5, ...] + [500, 500, ...]

위치 500에서는 더해진 500이 임베딩의 0.3을 압도한다. 더한 결과가 "어떤 글자인지"가 아니라 "몇 번째인지"만 보이게 되고, 글자 의미가 사라진다. 이것이 "임베딩을 망가뜨린다"는 의미이다.

사인/코사인은 위치가 아무리 커도 값이 -1~1에 머문다. 그래서 위치가 1000이어도 더해지는 크기가 일정하다.



### 이 강의 코드에서의 균형

**step6_transformer.py**보면 크기를 맞추는 장치가 있다.

* 임베딩 초기값은 표준편차 0.1이다(119번 줄). 위치 인코딩(-1~1)보다 훨씬 작다.
* 그래서 128번 줄에서 임베딩에 $\sqrt{d_model}=\sqrt{32}\approx5.7$을 곱한 뒤 위치 인코딩을 더한다.



` x = self.emb.take(idx) * self.scale + self.pe[:T]`



곱하면 임베딩 크기가 약 $0.1\times 5.7\approx0.57$ 정도가 되어, 위치 인코딩과 비슷한 수준이 된다. 원 논문(Attention Is All You Need)도 같은 방식이다.



### 정리 

* 위치 인코딩이 -1~1로 제한된다는 것은 위치가 커져도 더해지는 크기가 안 커진다는 뜻이다.
* 다만 -1~1이면 항상 안전한 것은 아니고, 임베딩 쪽 크기와 균형이 맞아야 한다. 그 균형을 맞추는 것이 $\sqrt{\text{d\_model}}$ 곱이다.

## 위치 인코딩 아이디어: 시계의 바늘

차원마다 다른 파형을 사용하다고 했는데, 이는 SIN, COS의 값에 대입되는 값이 다르다는 의미이다. 즉 입력되는 값이 달라진다는 의미이다.

수식으로 보면
$$
\text{각도} = pos / 10000^{(2i / \text{d\_model})}\\ \\
\text{PE}[pos,\ 2i] = sin(각도)\\ \\
\text{PE}[pos,\ si+1] = cos(각도)
$$
d_model=8이면 차원 쌍 i=0, 1, 2, 3의 나눈는 값은 이렇다.

| 차원 쌍 i | 나눈 값 | 위치 1칸당 각도 변화 | 파형         |
| --------- | ------- | -------------------- | ------------ |
| 0         | 1       | 1                    | 빠르게 진동  |
| 1         | 10      | 0.1                  | 느림         |
| 2         | 100     | 0.01                 | 더 느림      |
| 3         | 1000    | 0.001                | 거의 안 변함 |

위치 **pos=5**라면 i=0은 sin(5), i=1은 sin(0.5), i=2는 sin(0.05), i=3은 sin(0.005)를 계산한다. 같은 위치인데 sin에 들어가는 값만 다르다.



### 시계 비유와 연결

* 각도가 빨리 커지는 차원(i=0)은 초침이다. 위치 1칸마다 크게 움직여서 가까운 위치를 구분한다.
* 각도가 천천히 커지는 차원(i=3)은 시침이다. 위치가 한참 지나야 움직여서 먼 위치를 구분한다.



### 두 가지 보충

* 한 쌍의 sin과 cos는 같은 각도를 쓴다. 2i번 차원이 sin(각도), 2i+1번 차원이 cos(각도)이므로, 차원 8개는 각도 4종류가 된다.
* 정확히는 "독립변수의 크기"가 아니라 "독립변수에 곱해지는 계수(주파수)"가 다른 것이다. **pos**는 같고, **pos $\times$ (1/나누는 값)**에서 계수가 다르다. 이 계수가 파형이 얼마나 빨리 진동하는지를 정한다.

## "가까운 위치일수록 내적이 크다"의 의미

두 위치의 위치 인코딩 벡터를 내적하면, 위치가 가까울수록 값이 크다. 즉 벡터 모양이 비슷하다는 뜻이다.



### 내적이 크다는 것

내적은 두 벡터가 얼마나 같은 방향을 향하는지 재는 값이다. 크면 비슷하고, 작으면 덜 비슷하다. 어텐션의 **Q$\cdot$K** 점수도 이 내적이다.



### 실제로 계산한 값

**d_model=32**에서 위치 10과 거리 k만큼 떨어진 위치의 내적이다.

| 거리 k | 0     | 1     | 2     | 4     | 8     | 16   | 32   |
| ------ | ----- | ----- | ----- | ----- | ----- | ---- | ---- |
| 내적   | 16.00 | 15.31 | 13.73 | 11.66 | 10.52 | 7.92 | 9.63 |

* 자기 자신(거리 0)이 가장 크고, 멀어질수록 대체로 줄어든다.
* 위치 30에서 같은 계산을 해도 똑같은 값이 나온다. 내적이 절대 위치가 아니라 두 위치의 차이에만 달려 있다는 뜻이다.
* 거리 0의 값 16은 **d_model/2**이다. 차원 쌍마다 $\text{sin}^2 + \text{cos}^2 = 1$이고 쌍이 16개이기 때문이다.



### 왜 그런가

한 쌍(sin, cos)의 내적은 **$\cos(w\cdot \text{pos}_1)\cdot(w\cdot\text{pos}_2) + \sin(w\cdot\text{pos}_1)\cdot\sin(w\cdot\text{pos}_2) = \cos(2\cdot(\text{pos}_1-\text{pos}_2))$**이다. 각도 차이만 남는다. 모든 쌍을 더하면 $\sqrt{\cos(w_i\cdot\text{거리})}$가 된다.



거리가 작으면 각도 차이가 작아서 cos가 1에 가깝고, 거리가 크면 쌍마다 cos 값이 제각각 흩어져 합이 줄어든다. 시계로 말하면 시각이 브싯하면 바늘 모양이 비슷한 것과 같다.



### 주의할 점

* 항상 줄어드는 것은 아니다. 거리 32의 내적 (9.63)이 거리 16(7.92)보다 크다. 경향이 그렇다는 것이지 엄밀하게 단조 감소하지는 않는다.
* 어텐션에 곧 바로 쓰이는 것은 아니다. 실제 어텐션은 위치 인코딩이 더해진 입력에 **Wq, Wk**를 곱한 뒤 내적하므로, 이 성질이 그대로 점수가 되지는 않는다. 모델이 위치 관계를 학습하기 쉽게 해 주는 바탕이라고 보는 편이 정확하다.

## pos = np.arange(max_len)[:, None]

`np.arange(max_len)`으로 0부터 `max_len-1`까지의 위치 번호를 만들고, `[:, None]`으로 그것을 세로 열`((max_len, 1) 모양)`로 바꾸는 코드이다.



### 단계별로 보기

**max_len=4**라고 하면:

```python
import numpy as np

np.arange(4)			# [0 1 2 3]		모양 (4,) <- 1차원
np.arange(4)[:, None]	# [[0]
						#  [1]
    					#  [2]        
        				#  [3]]			모양 (4, 1) <- 2차원, 세로 열
```

- `np.arange(4)`는 위치 0, 1, 2, 3을 담은 1차원 배열이다.
- `[:, None]`에서 :는 "기존 축은 그대로 둔다", None은 "크기 1짜리 새 축을 끼워 넣는다"는 뜻이다. 두 번째 자리에 넣었으므로 열 방향 축이 생긴다.
- `np.newaxis`는 None의 별명이라 `[:, np.newaxis]`와 같다.



### 왜 세로로 세우는가?

바로 아래 줄이 있다.

```python
i = np.arange(0, d_model, 2)[None, :]		# (1, d_model / 2)	가로 행
angle = pos / (10000 ** (i / d_model))		# (max_len, d_model / 2)
```

`pos`는 `(max_len, 1)`, `i`는 `(1, d_model . 2)`이다. NumPy는 크기가 1인 축을 다른 배열 크기에 맞춰 늘려서 계산한다(브로드캐스팅). 그 결과 모든 (위치, 차원 쌍) 조합의 각도가 한 번에 나온다.



`max_len=3, d_model=4`이면 이렇게 된다.



```text
pos (3, 1)		i (1, 2)		나눈 값 (1, 2)
[[0]			[[0, 2]] ->		[1, 100]
 [1]
 [2]]
 
 angle (3, 2)
 [[0, 0   ],	<- 위치 0
  [1, 0.01],	<- 위치 1
  [2, 0.02]]	<- 위치 2
```

행은 위치, 열은 차원 쌍이다. 앞에서 말한 "위치는 같고 차원마다 나눈 값이 다르다"가 이 표 한 장으로 계산된다.



`[: None]`을 빼면

**pos**가 **(max_len, )**이고 **i**가 **(1, d_model/2)**이면 두 모양이 맞지 않거나, 맞더라도 의도와 다른 방향으로 계산된다. 반복문 없이 표를 들려면 한쪽은 세로, 한쪽은 가로로 세워야 한다. 반복문 없이 표를 만들려면 한쪽은 세로, 한쪽은 가로로 세워야 한다.

## 인과 마스크 (Casual Mask)

"인과(因果)"는 원인과 결과를 뜻하고, 영어 casual의 번역이다. 인과 마스크는 "원인(과거)만 결(현재)"에 영향을 줄 수 있다"는 규칙을 지키게 하는 마스크이다.



### 왜 이런 이름인가?

시간 순서로 보면 과거는 현재의 원인이 될 수 있지만, 미래는 현재의 원인이 될 수 없다. 글을 쓰는 모델(GPT)에 이 규칙을 그대로 적용한다.

* 위치 3의 단어를 예측할 때는 위치 0, 1, 2(과거)와 자기 자신만 볼 수 있다.
* 위치 4, 5, ...(미래)는 볼 수 없다.



### 마스크 모양

토큰이 4개일 때 "볼 수 있는가"를 표로 쓰면 아래와 같다. 행이 나(Query), 열이 참고 대상(Key)이다.



```text
		0  1  2  3
토큰 0 [ 0  X  X  X ]
토큰 1 [ 0  0  X  X ]
토큰 2 [ 0  0  0  X ]
토큰 3 [ 0  0  0  0 ]
```

대각선 위쪽(미래)이 X이고, 아래쪽 삼각형만 0이다. 가릴 자리의 점수를 아주 작은 값($-\infin$에 가까운 값)으로 바꾸면 softmax 후 가중치가 0이 된다.



### 왜 꼭 필요한가?

학습할 때 모델은 문장 전체를 한 번에 받고, 각 위치마다 "다음 글자"를 맞히도록 훈련한다. 마스크가 없으면 위치 3이 위치 4의 정답 글자를 직접 보고 베껴 버린다. 시험지를 훔쳐보는 것과 같다. 학습 때는 정답을 맞히지만, 실제 생성할 때는 미래가 없으므로로 아무것도 못 한다.



### 다른 이름

* 인과 마스크 = casual mask = look-ahead mask (앞을 못 보게 하는 마스크)
* 인코더형(BERT 등)은 미래도 볼 수 있어서 이 마스크를 쓰지 않는다. 슬라이드의 "마스크 없음 vs 인과 마스크" 히트맵이 이 차이이다.

## 헤드(head)

멀티헤드 어텐션 안에서 어텐션을 따로 수행하는 독립된 한 묶음이다.

각 해드가 자기만의 Q, K, V로 "누구를 볼지" 혼자 결정한다.



### 구조

헤드 하나는 아래 구조를 갖는다.

* 자기 몪의 Q, K, V (`d_model`을 나눈 `d_head` 길이)
* 자기만의 어텐션 가중치표 `(n, n)`
* 자기만의 출력 `(n, d_head)`

`d_model=32`, 헤드 4개이면 다음과 같이 구성

```text
입력 (n, 32)
  |- 헤드 1: (n, 8) -> 어텐션 -> (n, 8)
  |- 헤드 2: (n, 8) -> 어텐션 -> (n, 8)
  |- 헤드 3: (n, 8) -> 어텐션 -> (n, 8)
  └- 헤드 4: (n, 8) -> 어텐션 -> (n, 8)
  		이어 붙이기 -> (n, 32) -> Wo -> (n, 32)
```

헤드끼리는 계산 중에 서로 영향을 주지 않고, 마지막에 이어 붙인 뒤 Wo를 곱할 때 한꺼번에 섞인다.



### 이름의 뜻

`head`는 읽는 장치(자기 테이프의 읽기 헤드)처럼 입력을 읽는 "시선" 하나를 가리킨다. 4개 헤드는 같은 문장을 4개의 시선으로 동시에 읽는 셈이다.



### 헤드마다 무엇을 보는가?

사람이 역할을 정해 주지 않는다. 가중치가 처음에는 랜덤이고 학습하면서 헤드마다 달라진다. 학습된 큰 모델을 분석하면 어떤 헤드는 바로 앞 단어를, 어떤 헤드는 문장 첫머리를 주로 보는 경향이 관찰되기도 한다. 다만 항상 깔끔하게 나뉘지는 않고, 작은 모델에서는 구분이 흐리다.



### 코드에서는

헤드는 별도 객체가 아니라 배열의 한 축이다. 앞에서 본 코드의 `(heads, n, d_head)`에서 첫 번째 축이 헤드이고, `reshape`와 `transpose`로 그 축을 만들어 한꺼번에 계산한다.

## FFN(Feed-Forward Network, 피드 포워드 신경망)

FFN은 트랜스포머 블록 안에서 각 토큰 벡터를 개별적으로 가공하는 작은 2층 신경망이다.



### FFN의 역할

어텐션은 토큰들 사이의 정보를 섞고, FFN은 섞인 정보를 토큰 하나씩 따로 처리한다.

* 토큰마다 같은 가중치로 독립적으로 계산한다. 토큰끼리는 이 단계에서 서로 보지 않는다.
* 어텐션은 사실상 가중 평균(선형 연산)이라 표현력이 제한된다. FFN의 비선형 함수가 복잡한 변환을 가능하게 한다.
* 어텐션이 "누구에게서 가져올지"라면 FFN은 "가져온 것으로 무엇을 계산할지"이다.



### 4d (4배 확장)

강의 코드는 이렇게 생겼다.

> (n, d_model) $\rightarrow$ Linear $\rightarrow$ (n, 4\cdot d_model) $\rightarrow$ Activate $\rightarrow$ Linear $\rightarrow$ (n, d_model)



- 4d의 ` d`는 `d_model`이다. 32차원이면 중간에 128차원으로 넓혔다가 32차원으로 되돌린다.
- 넓히는 이유는 중간에 더 많은 칸을 확보해 비선형 처리를 풍부하게 하기 위해서이다. 그다음 다시 `d_model`로 줄여야 입력과 출력의 모양이 같아져서 잔차 연결과 블록 쌓기가 가능하다.
- 4배는 원 논문(Attention In All You Need)의 선택이고 이후 GPT 계열도 관례로 따른다. 수학적으로 정해진 값은 아니어서 2배나 8배도 가능하다.
- 파라미터는 약 $8\cdot \text{d\_model}^2$로, 블록에서 어텐션(약 $4\cdot\text{d\_model}^2$)보다 두 배 크다. 모델 파라미터 대부분이 FFN에 있다. 모델 파라미터 대부분이 FFN에 있다.



### GELU

중간의 활성화 함수(비선형 함수)이다. 선형 층만 쌓으면 아무리 깊으도 선형 하나와 같아지므로 중간에 비선형이 반드시 필요하다.

| 함수 | 식                | 모양                                    |
| ---- | ----------------- | --------------------------------------- |
| ReLU | max(0, x)         | 0에서 꺾임. 음수는 전부 0               |
| GELU | $x \cdot \Phi(x)$ | 0근체에서 부드럽게 휨. 음수도 약간 통과 |

$\Phi(x)$는 표준 정규분포의 누적확률이다. 직관은 "x가 클수록 거의 그대로 통과시키고, 음수일수록 거의 0으로 누르되 그 사이를 매끄럽게 잇는다"이다.

GELU는 매끄러워서 기울기가 안정적이고, GPT와 BERT 등이 이를 쓴다. 개념은 ReLU의 부드러운 친척이다.



### 이 강의 코드에서의 차이

두 버전이 다르다.

* NumPy `step6_transformer.py`는 `relu`를 쓴다. GELU를 직접 구현하면 자동미분 엔진에 연산을 더 추가해야 해서 단순하게 간 것이다.
* PyTorch `step4_block.py`는 `nn.GELU()`를 쓴다.



두 버전의 활성호 함수가 다르다는 점을 학생이 헷갈릴 수 있어서 슬라이드에 짚었는지 확인하면 좋다.

## 잔차(Residual) 연결에서 수정분이라?

수정분은 어텐션이나 FFN 같은 서브층이 계산해 낸 출력 자체이다. 그 출력을 원래 입력 x에 더하는 거시 잔차연결이다.



### 계산 방법

강의 블록은 Pre-LN 구조라서 두 번 더한다.

```text
x = x + attention(layernorm(x))		# 수정분 1: 어텐션이 만든 값
x = x + ffn(layernorm(x))			# 수정분 2: FFN이 만든 값
```

* `layernorm(x)`로 값의 크기를 정돈한 뒤 서브층에 넣는다.
* 서브층의 출력이 수정분이다. 별도 계산이 아니라 어텐션과 FFN의 결과 그대로이다.
* 모양은 입력과 같은 `(n, d_model)`이라야 더 할 수 있다. 어텐션과 FFN이 입출력 모양을 같게 만든 이유가 이것이다.



### 수정분의 의미

`x`는 그 토큰에 대해 지금까지 알아낸 정보이다. 서브층은 이를 통째로 새로 만들지 않고 "여기에 이만큼 보태자"만 계산한다.

- 어텐션의 수정분은 "다른 토큰에서 가져온 정보"이다.
- FFN의 수정분은 "그 정보를 가공해서 얻은 새 특징"이다.

예를 들어 "그것"의 벡터에서 출발해, 어텐션이 "동물이라는 정보"를 더해 주는 식이다. 원래 정보는 그대로 남고 새 정보가 얹힌다. 여러 층을 거치며 벡터가 조금씩 다듬어진다.



### 왜 이렇게 하는가

- 학습이 안정된다. 층이 깊어도 기울기가 더하기 경로를 타고 앞쪽 층까지 거의 그대로 전달된다. 더하기의 미분은 1이라 기울기가 줄지 않기 때문이다.
- 처음에 망가질 위험이 적다. 서브층 가중치가 랜덤이어도 수정분이 작으면 입력이 대체로 보존된다.
- 서브층이 "무엇을 바꿀지"만 학습하면 된다. 수정분이 0에 가까워지면 그 층은 사실상 건너뛰는 것이고, 원본 전체를 다시 만드는 것보다 쉬운 문제이다.



### 정리

수정분은 사람이 정하는 값이 아니라, 학습으로 만들어진 서브층의 출력이다. 잔차 연결의 핵심은 "원본은 보존하고, 필요한 만큼만 고친다"이다.

블록의 정확한 순서(Pre-LN)는 앞선 작업 기억에 따랐고, 위 코드는 설명용으로 줄여 쓴 것이라 실제 Block의 변수명과 다르다. 슬라이드 본문은 열어 보지 않았다.

## LayerNorm (층 정규화)

LayerNorm(층 정규화)은 토큰 벡터 하나의 값들을 평균 0, 분산 1로 맞춘 뒤, 학습 가능한 크기와 이동값을 적용하는 연산이다. 값의 크기를 정돈해서 학습을 안정시킨다.



### 계산

토큰 벡터 하나(길이 **d_model**)마다 따로 계산한다.

>평균 $\mu = means(x)$
>
>분산 $\sigma^2 = var(x)$
>
>$\hat{x} = (x - \mu) / \sqrt{(\sigma^2 + \varepsilon)}$	$\leftarrow$ 평균 0, 분산 1로 만들기
>
>$y = \gamma \cdot \hat{x} + \beta$	 	      $\leftarrow$ 학습되는 크기($\gamma$)와 이동($\beta$)

$\varepsilon$은 0으로 나누는 것을 막는 아주 작은 값(예: 1e-5)이고, $\gamma$는 1, $\beta$는 0으로 시작한다.



#### 손계산 예 ($\varepsilon$ 무시): x = [1, 2, 3, 4]

* 평균 2.5, 분산 1.25, 표준편차 $\approx$ 1.118
* $\hat{x} \approx [-1.342, -0.447, 0.447, 1.342]$

```python
import numpy as np

def layernorm(x, gamma, beta, eps=1e-5):
    mu = x.mean(axis=-1, keepdims=True)
    var = x.var(axis=-1, keepdims=True)
    return gamma * (x - mu) / np.sqrt(var + eps) + beta
```

`axis=-1`이 핵심이다. 마지막 축(`d_model`) 방향으로 평균을 내므로 토큰마다 독립적으로 정규화된다.

## CTX(context length)

CTX는 context length(문맥 길이)의 줄임말로, 모델이 한 번에 읽는 글자( 토큰) 수이다. 이 강의에서는 32이다.



step6_transformer.py의 학습 루프를 보면 다음과 같다.

```python
CTX, BATCH, STEPS = 32, 16, 600
starts = rng.integers(0, len(data) - CTX - 1, size=BATCH)
x = np.stack([data[s:s + CTX] for x in starts])			# 입력: CTX글 자
y = np.stack([data[s + 1: s+ CTX + 1] for s in starts]) # 정답: 한 칸 뒤
```



* 글 전체에서 랜덤 위치 s를 잡고, 거기서 32글자를 잘라 입력 x로 쓴다.
* 정답 y는 같은 구간을 한 칸 뒤로 민 32글자이다. 위치마다 "다음 글자"를 맞히는 문제가 된다.
* 입력 모양은 `(BATCH, CTX)=(16, 32)`이다.



모델과 연결되는 부분

* `GPT(..., max_len=CTX)`: 위치 인코딩 표를 `CTX`개 위치만큼 만든다. 모델이 알고 있는 위치는 0~31뿐이다.
* 인과 마스크의 크기도 `(CTX, CTX)`가 되고, 어텐션 점수표는 `(CTX, CTX)` 크기이다.
* 비용: 어텐션 계산량은 **CTX$^2$**에 비례하므로 두 배로 늘리면 약 네 배가 된다.



### 생성할 때

학습 때 32글자까지만 봤으므로, 생성할 때도 최근 CTX글자만 잘라서 넣는다. 207번 줄에서 `generate(model, start, 120, itos, CTX)`로 `CTX`를 넘기는 이유이다. 생성된 글이 길어져도 모델은 마지막 32글자만 보고 다음 글자를 정한다.



### 같은 개념의 다른 이름

`block_size`, `seq_len`, `max_len`, `컨텍스트 윈도우`는 같은 개념이다. 실제 대형 모델의 컨텍스트 윈도우는 수만~수십만 토큰이다.

## 교차 엔트로피

교차 엔트로피(cross-entropy)는 모델이 정답에 얼마나 높은 확률을 줬는지 재는 손실값이다. 정답 글자에 준 확률이 낮을수록 값이 크고, 1에 가까울수록 0에 가깝다.



### 공식

정답 토큰의 확률이 p라면 다음곽 타다.

> 손실 = $-ln(p)$

토큰이 여러 개면 각 위치의 손실을 평균 낸다.

| 정답에 준 확률 p | 손실 $-ln(p)$ | 해석               |
| ---------------- | ------------- | ------------------ |
| 1.0              | 0             | 완벽               |
| 0.7              | 0.357         | 꽤 잘 맞힘         |
| 0.25             | 1.386         | 4지 선다 찍기 수준 |
| 0.1              | 2.303         | 거의 틀림          |
| 0.01             | 4.605         | 크게 틀림          |

틀린 확신일수록 손실이 급격히 커져서, 모델이 정답 쪽 확률을 올리도록 강하게 압박한다.

다음 글자 맞히기에서의 계산

1. 모델이 어휘 전체 대한 점수(logits) (V,)를 낸다.
2. softmax로 확률로 바꾼다.
3. 정답 글자의 확률만 꺼내 $-ln$을 취한다.

```python
import numpy as np

def cross_entropy(logits, target):			# logits: (V, ), target: 정답 번호
    z = logits - logits.max()				# 수치 안정성
    log_probs = z - np.log(np.exp(z).sum())	# log softmax
    return -log_probs[target]
```

"one-hot과 연결" 설명을 기억하면, 정답을 one-hot 벡터로 보고 $-\sum \text{정답}\times ln(\text{예측})$을 계산하면 정답 자리 하나만 남아서 위의 $-ln(p)$와 같아진다. 이 이름이 "교차"인 것도 정답 분포와 예측 분포를 맞대어 비교한다는 뜻이다.



### 학습 시작 값의 의미

아무것도 모르는 모델은 모든 글자에 같은 확률 1/V를 준다. 그러면 손실이 ln(V)이다. V=28이면 ln 28 ≈ 3.33입니다. 이 강의 NumPy 모델의 학습 시작 loss는 3.724였는데, 초기 가중치가 랜덤이라 이론값 3.33보다 조금 높은 것으로 보인다. loss가 3.724에서 0.108까지 내려갔다는 것은 정답에 평균 약 90%의 확률을 준다는 뜻이다(e^-0.108 ≈ 0.90).



### 구현 이름

- NumPy 버전: 자동미분 엔진의 cross_entropy 연산
- PyTorch: F.cross_entropy(logits, targets) (softmax를 내부에서 처리하므로 logits를 바로 넣음)

## -를 붙이는 이유는?

손실을 **"작을수록 좋은 양수"**로 만들기 위해서이다.



### 이유

확률 p는 0~1 사이이다. 이 범위에서 $ln(p)$는 항상 0 이하의 음수이다(ln 1 = 0, ln 0.5 = -0.69, ln 0.1 = -2.3).

- ln(p)는 정답 확률이 높을수록 0에 가깝고 낮을수록 크게 음수라서, 그대로 쓰면 "클수록 좋은" 점수(최대화할 값)가 된다. 이를 로그 가능도(log-likelihood)라고 한다.
- 경사 하강법과 손실이라는 개념은 "작을수록 좋고 0이 최선"인 관례를 따른다. 그래서 부호만 뒤집어 -$ln(p)$로 쓴다.

- 경사 하강법과 손실이라는 개념은 "작을수록 좋고 0이 최선"인 관례를 따른다. 그래서 부호만 뒤집어 $-ln(p)$로 쓴다.



**즉 "최대화 문제"를 "최소화 문제"로 바꾸려고 붙인 부호이다.**



### 기울기와의 관계

부호를 빼도 학습은 가능하다. 다만 $ln(p)$를 최대화하는 상승법(gradient ascent)으로 바꿔야 한다. 부호를 붙이면 다른 손실(MSE 등)과 똑같이 "기울기의 반대 방향으로 이동"하는 하강법 한 가지로 통일된다. 결과는 같고 코드 규칙만 통일되는 것이다.



### 확인용 숫자

softmax와 합친 교차 엔트로피의 기울기는 아주 간단하다.

> $\partial\text{손실}\ /\ \partial\text{logits} = \text{예측 확률} - \text{정답(one-hot)}$

정답 자리는 p - 1(음수라서 점수를 올리는 방향), 나머지는 p(양수라서 점수를 내리는 방향)이다. 부호를 붙인 덕분에 이 식이 깔끔하게 나온다.

## 경사하강법의 w는?

**w**는 모델의 가중치, 즉 학습으로 바꿔 가는 숫자이다. 경사 하강법은 손실이 줄어드는 방향으로 **w**를 조금씩 고치는 방법이다.



###  업데이트 식

w ← w - lr × (∂손실/∂w)
$$
w \leftarrow w - lr \times (\partial\text{손실}/\partial w)
$$

- $\partial{손실}/\partial w$는 **"w를 아주 조금 올리면 손실이 얼마나 변하는가"**를 나타내는 기울기이다.
- 기울기가 양수이면 **w**를 올릴 때 손실이 커진다는 뜻이므로 **w**를 줄인다. 음수이면 **w**를 키웁니다. 식 앞의 -가 이 방향을 맞춰 준다.
- lr(learning rate, 학습률)은 한 번에 움직이는 크기이다. 너무 크면 튀고 너무 작으면 느리다.



### 이 모델에서 w는 무엇인가

**w** 하나가 아니라, 모델의 학습 대상 숫자 전부를 가리킨다.

- 임베딩 표 E의 모든 값
- Wq, Wk, Wv, Wo의 모든 값
- FFN의 Linear 두 개의 가중치와 편향
- LayerNorm의 $\gamma$, $\beta$
- 마지막 출력층의 가중치



NumPy 모델은 이를 모두 합쳐 27,292개이다. 슬라이드의 **w**가 숫자 하나로 그려졌다면 그중 하나를 대표로 보인 것이다. 모든 **w**가 같은 식으로 동시에 갱신됩니다.



### 한 줄 예시

$w=3.0$, $\text{기울기}=2.0$, $lr=0.1$이면:
$$
w = 3.0 - 0.1 × 2.0 = 2.8
$$
기울기가 양수라서 **w**가 줄었고, 손실이 약간 줄어드는 쪽으로 이동했다.

강의 코드에서

실제 학습에서는 Adam을 쓴다. 기본 식은 같고, 기울기를 부드럽게 평균 낸 값을 쓰고 가중치마다 보폭을 자동 조절한다는 점이 다르다.

## 위상 정렬(topological sort)

위상 정렬(topological sort)은 "A는 B보다 먼저"라는 의존 관계가 있는 항목들을, 그 순서를 어기지 않게 한 줄로 세우는 방법이다.

방향이 있고 순환이 없는 그래프(DAG)에서만 가능하다.



### 일상 예

옷 입는 순서를 생각해 보면 이렇다.

>속옷 $\rightarrow$ 바지 $\rightarrow$ 신발
>
>양말 $\rightarrow$ 신발

**속옷, 양말, 바지, 신발**이나 **양말, 속옷, 바지, 신발**은 모두 올바른 순서이다. 반면 신발이 바지보다 앞에 오면 틀린다. 선행 항목이 항상 먼저 오기만 하면 되고, 답이 여러 개일 수 있다.



### 자동 미분에서 왜 필요한가?

> a, b $\rightarrow$ c = a $\cdot$ b $\rightarrow$ d = c + a $\rightarrow$ loss = d$^2$

역전파는 loss에서 시작해 거꾸로 기울기를 전파한다. 이때 노드 하나의 기울기는 그 노드를 쓴 모든 다음 노드의 기울기를 다 받은 뒤에 확정된다.

- 위 예에서 a는 c와 d 두 곳에서 쓰입니다. a의 기울기는 두 경로의 합이다.
- d나 c의 기울기가 확정되기 전에 a로 넘어가면 값이 덜 쌓인 채로 전파되어 틀린 결과가 나온다.

그래서 순전파 순서를 위상 정렬로 구한 뒤, 그 역순으로 _backward를 호출한다. "자기를 쓴 노드가 전부 먼저 처리되도록" 보장하는 것이다.



### 구현 (깊이 우선 탐색)

```python
def backward(self):
    order, seen = [], set()
    def visit(t):
        if t in seen: return
        seen.add(t)
        for p in t.parents:      # 부모(입력)를 먼저 방문
            visit(p)
        order.append(t)          # 부모가 모두 들어간 뒤 자신을 추가
    visit(self)
    self.grad = 1.0
    for t in reversed(order):    # 역순으로 기울기 전파
        t._backward()
```

order에는 입력이 앞, loss가 뒤에 오는 순서가 만들어지고, 이를 뒤집어서 loss부터 처리한다.

이 강의의 Tensor가 parents와 _backward 클로저로 구성된다는 점은 앞선 작업 기억에 따랐고, 위 코드는 같은 원리를 설명하려고 새로 쓴 것이다. step5_autograd.py의 실제 구현과 변수명은 대조하지 않았고 실행도 하지 않았다.

## backward()

`backward()`는 "결과가 나빴을 때, 각 숫자를 얼마나 고치면 결과가 좋아질지"를 거꾸로 거슬러 올라가며 알아내는 함수이다.



### 비유: 케이크 맛 문제

케이크가 너무 달다고 해 봅시다. 원인은 설탕, 시럽, 크림일 수 있다. 어떻게 고칠까요?

1. 맛을 본다. (결과)
2. 거꾸로 따져 본다. "크림이 이만큼, 설탕이 이만큼 달게 만들었네."
3. 책임이 큰 재료를 더 많이 줄인다.



**backward()는 이 2번을 컴퓨터가 하는 일이다.** 인공지능에서 "재료"는 모델의 숫자(가중치)이고 "너무
달다"는 "틀린 정도(손실)"이다.



#### 아주 작은 예

a = 2,  b = 3
c = a × b = 6
d = c + a = 8



d가 너무 크다면 a와 b를 얼마나 바꿔야 할까? backward()는 이렇게 알아낸다.

- b를 1 올리면 c가 a(=2)만큼 올라서 d도 2 올라갑니다. → b의 영향력: 2
- a를 1 올리면 c가 b(=3)만큼, 그리고 +a로 1이 더 올라서 d가 4 올라갑니다. → a의 영향력: 4

이 **"영향력"을 기울기**라고 부르고, a.grad = 4, b.grad = 2로 저장된다. 영향력이 큰 a를 더 많이 줄이면 d가 더 빨리 내려갑니다.



### 어떻게 거꾸로 가는가

계산은 앞으로 쌓인다.

> a, b  →  c  →  d

backward()는 이 길을 되짚는다.

1. d에서 출발합니다. (d의 영향력은 자기 자신이므로 1)
2. 한 칸씩 뒤로 가면서 "바로 앞 칸의 영향력 × 이번 연산의 영향 비율"을 곱해서 전달합니다. (연쇄 법칙)
3. 같은 숫자가 여러 길로 쓰였으면 영향력을 더합니다. a는 두 길로 갔으므로 합쳐서 4입니다.



되짚는 순서가 중요하다. 케이크 예에서 크림의 영향이 다 계산되기 전에 설탕으로 넘어가면 틀린 답이
나온다. 그래서 앞에서 설명한 위상 정렬로 "나를 쓴 쪽이 먼저 끝나도록" 순서를 정한다.



### 그다음은?

`backward()`가 끝나면 모든 숫자에 `.grad`(영향력)가 채워진다. 그다음 경사 하강법이 `w ← w - lr × grad`로 숫자를 조금씩 고친다. 이 과정을 600번 반복하면 모델이 점점 똑똑해진다.

> 앞으로 계산 (예측) → 틀린 정도 계산 → backward() → 숫자 고치기 → 반복

위 예시 숫자(a의 영향력 4, b의 영향력 2)는 실행하지 않는다.

## np.zeros_like()

기존 배열과 동일한 shape(크기)와 dtype(자료형)을 갖는 배열을 생성하고, 모든 요소를 0으로 초기화하는 함수이다.

```python
 numpy.zeros_like(a, dtype=None)
```

* a: 기준이 되는 배열
* dtype: 새로운 데이터 타입 (생략 시 원본과 동일)

#### 예

```python
import numpy as np

x = np.array([[1, 2, 3],
              [4, 5, 6]])

y = np.zeros_like(x)

print(y)
```

#### 출력

```text
[[0 0 0]
 [0 0 0]]
```

## np.ndindex()

`ndindex()`는 배열의 **모든 인덱스를 순회하는 iterator**를 만든다.

```python
import numpy as np

for idx in np.ndindex(2, 3):
    print(idx)
```

### 출력:

```text
(0, 0)
(0, 1)
(0, 2)
(1, 0)
(1, 1)
(1, 2)
```
