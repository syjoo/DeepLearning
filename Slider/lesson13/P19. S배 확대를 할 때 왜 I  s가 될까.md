# P19. S배 확대를 할 때 왜 I / s가 될까?

기본적으로 역방향 매핑이다. 



## 핵심

식의 A는 "출력 위치 $\rightarrow$ 입력 위치" 방향으로 쓰인다. 입력을 출력으로 옮기는 방향이 아니다. 그래서 "s배 확대"를 거꾸로 읽어야 한다.

#### 예시: 2배 확대 (s = 2)

중심에서 4칸 떨어진 출력 칸 P를 생각해보면

* 이미지를 2배로 키우면, 출력에서 중심으로부터 4칸 떨어진 곳에는 원래 2칸 떨어진 곳이 와 있다. (2칸 $\times$ 2배 = 4칸)
* 따라서 이 칸은 입력의 중심에서 2칸 떨어진 곳에서 값을 읽어 와야 한다.



식으로 다음과 같다:

$$
q − c = (p − c) / 2   →   A = (1/2)·I
$$


#### 정리

| 방향                 | 하는 일                                 | 행렬      |
| -------------------- | --------------------------------------- | --------- |
| 앞방향 (입력 → 출력) | 거리를 s배로 늘린다                     | s$\cdot$I |
| 역방향 (출력 → 입력) | 출력 거리를 s로 나눠 입력 거리를 구한다 | I/s       |

회전도 같은 원리입니다. 이미지를 θ만큼 돌리려면 읽어 오는 위치는 −θ 방향으로 돌려야 합니다. 그래서 역방향에서는 회전 행렬의 θ에 부호가 반대로 들어갑니다. 슬라이드의 회전 코드가 이 부호를 어떻게 처리했는지는 확인하지 않았습니다.



## 역방향 매핑



역방향 매핑(inverse mapping)은 이미지를 변환할 때 "입력의 각 칸이 어디로 가는가"를 계산하지 않고, "출력의 각 칸이 입력 어디에서 왔는가"를 계산하는 방식입니다.



### 두 방식 비교

|           | 앞방향 (forward)                 | 역방향 (inverse)                     |
| --------- | -------------------------------- | ------------------------------------ |
| 질문      | 입력의 이 칸은 출력 어디로 갈까? | 출력의 이 칸은 입력 어디에서 왔을까? |
| 반복 대상 | 입력의 모든 칸                   | 출력의 모든 칸                       |
| 하는 일   | 입력 값을 계산된 출력 위치에 씀  | 계산된 입력 위치의 값을 읽어 옴      |



### 앞 방향이 왜 문제인가?

예를 들어 이미지를 2배 확대한다고 하자. 입력 칸 하나가 출력의 (2배 간격으로 떨어진) 한 칸에만 쓰입니다.

입력:  ■ ■ ■          출력:  ■ □ ■ □ ■ □
                              □ □ □ □ □ □

□는 아무도 값을 쓰지 않은 구멍이다. 회전할 때도 소수 좌표가 반올림되면서 어떤 칸은 겹쳐 쓰이고 어떤 칸은 비게 된다.



### 역방향은 어떻게 해결하나

출력의 모든 칸을 하나씩 돌면서, 그 칸에 들어갈 값을 입력에서 가져옵니다.



$for$ 출력의 각 칸 $p$:
    $q = A·(p − c) + c + t$     ← 19쪽 식 (입력 위치 계산)
    출력[p] = 입력[q]          ← 거기 있는 값을 읽어 옴



모든 출력 칸이 반드시 한 번씩 값을 받으므로 구멍이 생기지 않습니다. 앞에서 $A$가 $I/s$, 즉 앞방향의 반대가 된 것도, 이 식이 "출력 → 입력" 방향으로 쓰이기 때문이다.



### 남는 문제

$q$가 2.7처럼 소수일 수 있습니다. 입력에는 정수 칸만 있으므로, 가장 가까운 칸을 읽거나(최근접) 주변 칸을 섞는(보간) 방법이 필요합니다. 이 슬라이드 이후에서 다루는지는 확인하지 않았습니다.
