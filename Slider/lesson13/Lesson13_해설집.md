## 1교시. 왜 데이터를 "늘려야" 할까?

### 1-1. 시험 문제를 통째로 외운 학생

시험공부를 하면서 문제집의 답을 **통째로 외운** 학생이 있습니다. 같은 문제가 나오면 100점이지만, 숫자만 살짝 바뀌면 틀립니다. 이 학생은 **풀이 방법**이 아니라 **문제집 모양**을 외웠기 때문입니다.

인공지능도 똑같습니다. 사진 몇 장으로만 공부하면 "이 사진이면 고양이"를 외워 버립니다. 이것을 **과적합(overfitting)** 이라고 합니다. 연구실에서는 학습 손실이 0에 가까워 완벽해 보이는데, 현장에서는 사진이 흔들리고, 기울고, 어둡기 때문에 성능이 뚝 떨어집니다.

### 1-2. 데이터 증강이란?

고양이를 가르칠 때 정면 사진 한 장만 보여주지 않고, **옆모습, 어두운 방, 멀리서 찍은 사진**도 보여줍니다. 고양이는 똑같은 고양이입니다. 달라진 것은 "찍힌 모습"뿐입니다.

이렇게 **정답(레이블)은 그대로 두고, 모습만 바꾼 새 샘플을 만들어 데이터를 늘리는 것**이 **데이터 증강(Data Augmentation)** 입니다.

핵심 낱말 세 개:

| 낱말 | 쉬운 뜻 |
|---|---|
| 레이블 보존 | 변환해도 정답이 그대로다 |
| 불변성(invariance) | 모습이 바뀌어도 모델의 대답이 안 바뀐다 |
| 강건성(robustness) | 현장의 지저분한 변화에도 잘 버틴다 |

### 1-3. 증강과 생성은 다릅니다

* **증강**: 원래 있던 사진에서 출발합니다. "3을 살짝 돌린 3"
* **생성**: 아무것도 없는 데서 새로 그립니다. "존재하지 않는 얼굴 만들기" (GAN, 확산 모델)

원본 교재의 소제목 "증강 vs. 일반화"는 영문 `Generation`을 잘못 옮긴 것이라 **"증강 vs. 생성"** 으로 바로잡았습니다.

### 1-4. 수식 13.1을 말로 풀어 보기

```
x' = T(x),    f(x') ≈ f(x),    label(x') = y
```

* `x`: 원래 사진, `y`: 그 사진의 정답
* `T`: 변환 (예: −15°~15° 사이에서 무작위로 돌리기)
* `x'`: 변환한 사진
* `f(x') ≈ f(x)`: 사진을 조금 돌려도 모델이 같은 답을 한다 (불변성)
* `label(x') = y`: 돌린 사진의 정답도 여전히 같다

**주의 (원본에 없는 보강)**: 물체 검출처럼 "물체가 어디 있는지"가 정답인 과제는 사진을 옮기면 정답 상자도 같이 옮겨야 합니다. 이때는 "불변"이 아니라 "함께 움직이는" 성질(동변, equivariance)이 필요합니다.

### 1-5. 언제 특히 도움이 될까?

1. **데이터가 적을 때**: 외울 수 없을 만큼 변형을 만들어 줍니다.
2. **클래스 수가 불균형할 때**: 적은 쪽을 더 많이 변형해 균형을 맞춥니다.
3. **다양성이 부족할 때**: 학습 사진은 낮, 시험 사진은 밤이라면 밝기 증강이 다리 역할을 합니다.

좋은 증강이면 보통 이런 모습이 나타납니다.

* 학습 손실은 **약간 올라갑니다** (더 어려운 문제를 풀게 되니까)
* 검증 손실은 **내려갑니다**
* 분포 밖(OOD) 데이터의 정확도가 **크게 오릅니다**

### 1-6. 이미지는 숫자의 표입니다

컴퓨터에게 사진은 **숫자가 가득한 표**입니다. 이 수업의 손글씨 숫자는 8×8칸이고, 각 칸은 0(흰색)부터 16(검정)까지의 밝기입니다.

* **돌리기·밀기·뒤집기** = 표의 숫자를 **다른 칸으로 옮기기**
* **밝기·대비·노이즈** = 칸 안의 **숫자 값을 바꾸기**

그래서 NumPy 배열 연산만으로 모두 만들 수 있습니다.

### 1-7. 가장 중요한 규칙: 레이블 일관성

6을 180° 돌리면 **9**처럼 보입니다. 그런데도 정답을 "6"이라고 붙이면 모델에게 **거짓말을 가르치는 것**입니다. 이것은 증강이 아니라 **의미적 손상**입니다. (원본의 "손성"은 "손상"의 오타입니다.)

**실험 (Step 2, `step2_label.py`)**: 숫자별 "평균 그림"과 가장 닮은 쪽을 정답으로 보는 아주 단순한 판정기를 만들었습니다.

* 6이 그려진 사진 181장을 180° 돌렸더니 **148장(82%)** 이 "9"로 읽혔습니다.
* 숫자 2를 좌우로 뒤집으면 "3"이나 "8"처럼 읽히는 경우가 많았습니다.

사람이 봐도 헷갈리는 변환은 의심하세요.

덤으로 알게 된 것: 이 판정기는 숫자를 **한 칸만 옮겨도** 정답 유지율이 90%에서 30%로 떨어집니다. 이동에 아주 약하다는 뜻이고, 이런 약점을 증강으로 메웁니다.

### 1-8. 도메인마다 허용되는 변환이 다릅니다

| 데이터 | 좌우 뒤집기 | 작은 회전 | 180° 회전 | 이유 |
|---|---|---|---|---|
| 손글씨 숫자 | ✕ | ○ | ✕ | 2·5, 6·9가 서로 바뀜 |
| 고양이/개 | ○ | ○ | ✕ | 거꾸로 선 고양이는 드묾 |
| 교통 표지판 | ✕ | △ | ✕ | 좌회전/우회전이 바뀜 |
| 흉부 X-선 | △ | △ | ✕ | 심장의 왼쪽 위치가 정보일 수 있음 |
| 위성 사진 | ○ | ○ | ○ | 위쪽이 정해져 있지 않음 |

(○ 안전, △ 전문가 확인, ✕ 정답이 바뀜)

## 2교시. 변환을 직접 만들어 봅시다 (Step 1)

### 2-1. 변환의 두 종류

1. **기하 변환(위치를 바꿈)**: 뒤집기, 이동, 회전, 확대, 크롭
2. **광도 변환(값을 바꿈)**: 밝기, 대비, 색 변화, 노이즈

### 2-2. 수평 뒤집기

```python
def flip_h(img):
    return img[:, ::-1]       # 열 순서만 거꾸로
```

`::-1`은 "끝에서 처음까지 거꾸로"라는 뜻입니다. `[[1,2,3],[4,5,6]]`은 `[[3,2,1],[6,5,4]]`가 됩니다. **대칭인 물체일 때만** 쓰세요. 숫자나 글자, 교통 표지판에는 쓰면 안 됩니다.

### 2-3. 회전·이동·확대는 "좌표 변환" 하나로

```
입력 위치 q = A · (p − c) + c + t
```

* `p`: 출력 그림의 한 칸의 위치, `c`: 그림의 가운데
* `A`: 2×2 행렬 (회전이면 cos/sin이 든 행렬, 확대면 `I/s`)
* `t`: 이동량

**왜 거꾸로 계산할까요?** 입력을 앞으로 옮기면 출력에 **값이 안 채워지는 구멍**이 생깁니다. 그래서 거꾸로, 출력의 모든 칸에 대해 "이 칸은 입력의 **어디에서** 왔을까?"를 물어보고 그 자리의 값을 가져옵니다. 구멍이 생기지 않습니다.

그런데 가져올 자리가 `2.3` 같은 **칸 사이**일 수 있습니다. 그때는 이웃 4칸을 거리에 비례해 섞습니다(**쌍선형 보간**).

작은 예 (손으로 해 보세요): 네 칸이 `0.2 0.8 / 0.4 1.0`이고 읽을 위치가 위에서 0.25, 왼쪽에서 0.5만큼이면

```
0.75·0.5·0.2 + 0.75·0.5·0.8 + 0.25·0.5·0.4 + 0.25·0.5·1.0
= 0.075 + 0.3 + 0.05 + 0.125 = 0.55
```

범위 밖은 0(흰색)으로 채워서, 회전하면 모서리가 비는 것입니다.

def shift(img, dy, dx):               # 이동: t만 바뀜 (부호가 -인 이유: 읽는 위치를 반대로 옮기면 그림이 밀림)

코드 끝의 **자체 검사**: 0도 회전과 0칸 이동은 원본과 같아야 합니다(`assert`). 오른쪽으로 한 칸 옮겨도 픽셀 값의 합은 18.375로 같았습니다.

### 2-5. 밝기와 대비

```
x' = clip( (x − 0.5)·c + 0.5 + b,  0, 1 )
```

* `b`(밝기): 모든 칸에 더하는 값. +0.2면 전체가 밝아져 배경이 회색이 됩니다.
* `c`(대비): **중간 회색 0.5를 기준으로** 늘이고 줄이는 배율. 1.5배면 어두운 곳은 더 어둡게, 밝은 곳은 더 밝게.
* `clip`: 값이 0~1을 넘지 않게 자릅니다. 빼먹으면 계산이 엉킵니다.

실행: 원본 평균 밝기 0.287 → +0.2 후 0.479 (일부 칸이 1을 넘어 잘려서 0.2보다 약간 작게 올랐어요).

### 2-6. 가우시안 노이즈, 색상 변화, 크롭

* **노이즈**: 칸마다 다른 작은 난수를 더합니다. `σ`가 크기입니다. 0.05는 거의 안 보이고, 0.4는 숫자가 사라집니다. (밝기는 모든 칸에 **같은** 값, 노이즈는 칸마다 **다른** 값!)
* **색상 변화(Color Jitter)**: 컬러 사진에서 색조·채도를 조금 흔듭니다. 바나나는 노랗고 신호등은 색이 정답이니 조심하세요.
* **크롭 & 리사이즈**: 무작위 영역을 잘라 원래 크기로 키웁니다. 확대+이동과 비슷합니다.

### 2-7. 과하면 독입니다

* 약한 증강(회전 ±10°, 이동 ±1칸, 노이즈 0.05): 아직 숫자로 읽힙니다.
* 너무 센 증강(회전 ±60°, 이동 ±3칸, 노이즈 0.4): 숫자의 구조가 사라집니다.

그래서 **항상 눈으로 확인**합니다. 새 변환을 쓰기 전 체크리스트:

## 3교시. 파이프라인과 종합 실험

### 3-1. 오프라인 vs 온라인

* **오프라인**: 변형본을 **미리 만들어 저장**합니다. 용량이 늘고, 변형이 **고정**(K가지뿐)입니다.
* **온라인**: **학습하는 중에 그때그때** 무작위로 변형합니다. 에포크마다 새로운 모습이고 저장 용량이 늘지 않습니다.

비유: 오프라인은 **미리 인쇄한 문제집 5권**, 온라인은 **매번 새 문제를 만들어 주는 선생님**입니다.

저장 용량 계산:

* 28×28 흑백 1,000장 ×10배 = 7,840,000 B ≈ **7.84 MB**
* 224×224 컬러 1,000장 ×10배 = 1,505,280,000 B ≈ **1.51 GB**

### 3-2. 파이프라인 만들기 (Step 3, `step3_pipeline.py`)

작은 변환들을 레고 블록처럼 이어 붙입니다.

```python
aug = Compose([RandomAffine(deg=10, shift=1), GaussianNoise(0.05)])
x_aug = aug(x_batch)      # 학습 루프 안에서 매 배치마다 호출
```

* `RandomAffine`: 샘플마다 **다른** 각도·이동량을 뽑아 한꺼번에 변환합니다 (`affine_grid` + `grid_sample`). Step 1의 `warp`와 같은 원리입니다.
* 각 변환이 "이미지를 받아 이미지를 돌려준다"는 같은 모양이라 줄줄이 이어 붙일 수 있습니다.
* **학습에만** 쓰고 검증·시험에는 쓰지 않습니다.

자체 검사: 모양 유지, 같은 입력을 두 번 넣으면 결과가 다름, 회전 0·이동 0이면 원본과 같음 — 모두 `True`.

실무에서는 `torchvision.transforms.v2`를 씁니다 (이 환경의 torchvision 0.20.1에서 실행 확인). 원본이 소개한 Albumentations도 대표 라이브러리이지만 이 환경에는 설치되어 있지 않아 직접 실행해 보지는 않았습니다.

### 3-3. 종합 실험 (Step 4, `step4_compare.py`)

**설계**: 같은 모델, 증강만 바꿉니다. 손글씨 8×8 중 **150장만** 학습하고 나머지로 검증합니다. 평가는 두 가지입니다.

1. 깨끗한 검증 이미지
2. 약하게 변형되고 노이즈가 낀 검증 이미지 ("현장"을 흉내)

**결과 (5회 평균)**

| 방식 | 학습 손실 | 검증 손실 | 깨끗한 검증 | 변형 검증 |
|---|---|---|---|---|
| 증강 없음 | 0.001 | 0.261 | 93.5% | 64.4% |
| 약한 증강(온라인) | 0.018 | 0.211 | 94.1% | **89.9%** |
| 오프라인 5배 | 0.005 | 0.279 | 93.3% | 85.4% |
| 너무 센 증강 | 1.691 | 1.800 | 37.2% | 32.6% |
| 좌우 뒤집기(나쁜 예) | 0.146 | 0.497 | 87.4% | 81.4% |

**읽는 법 (솔직하게)**

* 약한 증강은 학습 손실이 **올라가고**(0.001→0.018) 검증 손실은 **내려갑니다**(0.261→0.211). 원본이 말한 패턴 그대로입니다.
* 가장 큰 효과는 **변형이 낀 이미지**: 64.4% → 89.9%.
* 깨끗한 이미지의 정확도 차이(93.5 → 94.1)는 시드마다 흔들리는 폭(±0.5~1.3)과 비슷해서 "약간 나아졌다" 정도입니다. 증강은 마법이 아니라 **현장에서 일어날 변화에 대한 보험**입니다.
* 오프라인 5배는 온라인보다 낮습니다. 변형이 5가지로 고정되어 다양성이 부족해서입니다.
* 너무 센 증강, 정답을 깨는 좌우 뒤집기는 오히려 해롭습니다.

**함정: 학습을 충분히 오래 해야 합니다.** 같은 설정에서 학습 길이를 60 → 200으로 늘렸더니 약한 증강의 깨끗한 정확도가 89.2% → 94.1%가 되었습니다(증강 없음은 93.0% → 93.5%). 증강된 데이터는 어렵고 다양해서 배우는 데 시간이 더 걸립니다. 증강을 켰는데 성능이 떨어지면 ① 강도 ② 학습 길이 ③ 레이블 일관성을 먼저 의심하세요.

### 3-4. Best Practices

원본의 4가지:

1. **시각적 검증**: 증강된 배치를 항상 직접 본다.
2. **타당성 우선**: 클래스 정체성을 훼손하는 변환은 피한다.
3. **작고 조합 가능한 변환**: 큰 하나보다 작은 여러 개.
4. **도메인별 조정**.

보강: 5. 증강은 **학습 데이터에만**. 6. 강도는 작게 시작. 7. 난수 시드를 기록해 재현 가능하게.

### 3-5. 데이터 누수: 증강은 "분할한 뒤에"

원본 300장을 5배로 **늘린 뒤** 섞어서 학습/검증으로 나누면, 같은 원본의 쌍둥이 사진이 양쪽에 들어갑니다. 시험지를 미리 본 격이라 검증 점수가 **부풀려집니다**. 실험에서 변형본끼리 비교하면 **86.1% vs 79.2%** 로 6.9%p 차이가 났지만, 완전히 따로 둔 시험 점수는 93.0% vs 92.3%로 거의 같았습니다. 모델은 같은데 검증 점수만 거짓으로 높았던 것입니다.

### 3-6. [최신 자료] 더 나아간 기법들

| 기법 | 한 줄 설명 |
|---|---|
| **Cutout** | 이미지 일부를 가린다 (정답은 그대로) |
| **Mixup** | 두 이미지를 λ : (1−λ)로 섞고 정답도 같은 비율로 섞는다 |
| **CutMix** | 이미지 조각을 다른 이미지에 붙이고 정답은 넓이 비율로 섞는다 |
| **AutoAugment / RandAugment / TrivialAugment** | 어떤 증강을 쓸지 자동으로 정하거나 무작위로 고른다 (`v2.RandAugment` 등) |
| **TTA** | 시험 때도 여러 번 변형해 예측을 평균한다 |

Mixup 손계산: λ=0.7, x₁=[1,0,0.4](고양이), x₂=[0,1,0.8](개)이면 섞인 입력 `[0.7, 0.3, 0.52]`, 섞인 정답 `[0.7, 0.3, 0]`. 모델은 "고양이 70%, 개 30%"라는 부드러운 정답을 배웁니다.

**Step 5 결과 (`step5_advanced.py`, 약한 증강에 추가, 5회 평균)**

| 방식 | 깨끗한 검증 | 변형 검증 | 깨끗한 검증 + TTA(16회) |
|---|---|---|---|
| 없음 | 94.1% | 89.9% | 95.4% |
| Cutout | 93.2% | 88.4% | 94.1% |
| Mixup | 94.6% | 90.8% | 95.1% |
| CutMix | 93.8% | 89.8% | 94.7% |

8×8처럼 아주 작은 이미지에서는 Cutout·CutMix가 도움이 안 됩니다(가릴 곳이 없고 구조가 쉽게 사라짐). Mixup의 이득도 오차 범위 근처입니다. 이 기법들은 큰 이미지·큰 모델에서 효과가 보고된 것이므로 **내 데이터에서 직접 실험**해야 합니다. TTA는 94.1 → 95.4%로 올랐지만 추론 시간이 16배가 됩니다.

def random_brightness_contrast(img, rng, b_max=0.2, c_lo=0.8, c_hi=1.2):
    b = rng.uniform(-b_max, b_max)       # 이미지 한 장당 b 하나
